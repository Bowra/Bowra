# 初始化 Bowra 社区版

[English](community-setup.md) | 简体中文

社区版无需商业许可证、续期或内置用户数限额。运行者自行提供基础设施和模型凭据；团队权限、账号暂停及配置的积分预算继续生效。

## 首次启动

1. 使用社区版应用构建和全新的持久数据目录。保留部署配置中生成的 `BOWHEAD_FERNET_KEY` 与 `BOWHEAD_JWT_SECRET`；更换加密根密钥可能导致已保存的凭据无法读取。
2. 使用镜像自带的启动命令。程序先校验安装来源，再执行不可变数据库迁移并登记新的社区安装。来源未知或商业版数据库会在迁移前被拒绝；这类数据应继续使用原商业版构建。
3. 在应用服务器获取首位所有者初始化凭据：

   ```sh
   docker compose exec app /app/.venv/bin/python -m bowhead_gateway.installation setup-token
   ```

   本地 Python 仓库可使用 `uv run python -m bowhead_gateway.installation setup-token`，保持相同数据库和环境。命令仅在尚未完成初始化时显示凭据，不要将其放入 issue、截图或日志。

4. 打开应用 `/activate/` 页面，输入凭据、团队名称、所有者邮箱与强密码。仅一个提交能够完成初始化；重复或并发提交不能新增第二位所有者。
5. 用创建的账号登录，配置团队模型凭据并完成常规设置清单。通过支持的团队管理流程添加成员；邀请或找回密码邮件需要邮件服务配置和合适的公开入口。

初始化凭据由持久加密根及安装标识派生，完成初始化后失效。初始化前不开放普通 API 写入及账号创建；公开状态接口不会泄露初始化凭据或所有者登录凭据。

## 重启、升级和恢复

待初始化或已初始化实例重启会保留安装身份。数据库、对象数据和持久密钥须一起备份。首次迁移若在登记来源前中断，生成的未知数据库会被准入拒绝；检查并恢复对应的首次启动前备份，不能仅为绕过准入而将未知数据库标记为社区版。

社区升级商业版前先停止全部社区版应用及 worker 进程，再备份完整恢复集，保留全部密钥和数据，使用相同或更新版本的商业应用。首次商业准入记录版本转换。由已有团队负责人或管理员登录商业管理页，上传匹配已有团队 ID 的有效签名许可证。用户、所有权和资源继续保留，公开首位所有者激活接口不能创建替代管理员。升级后遵循商业版席位、到期和宽限期规则。不支持商业版自动降为社区版，许可证过期也不例外。不支持社区版与商业版进程同时访问同一数据库。

开发环境手动启动 Uvicorn 前先执行镜像对应的准备流程：

```sh
uv run python -m bowhead_gateway.installation prepare --migration-command .venv/bin/bowhead
```

该命令要求使用迁移管理的 `bowhead.db` 路径，并处理八个数据库目标。`BOWHEAD_DEPLOYMENT_MODE` 继续仅控制出站 URL 策略，不用于选择版本或绕过安装准入。
