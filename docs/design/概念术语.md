# Community 概念与稳定标识

[English](concepts.en-US.md) | 简体中文

这些命名与隔离规则适用于共享 Community 代码。产品文案变化时，仍应保留已存储的字段名。

## 独立边界

| 概念                               | 含义                                   | 稳定标识                                                  |
| ---------------------------------- | -------------------------------------- | --------------------------------------------------------- |
| Team（团队）                       | 成员关系、管理与租户隔离。             | `team_id`、`teams`、`team_members`                        |
| Space（空间）                      | 团队内的协作、知识、会话与访问。       | `workspace_id`、`workspaces`、`workspace_members`、`ws_*` |
| Datarc workspace（北极九章工作区） | 按当前用户解析的外部数据／查询上下文。 | `datarc_workspace_id`                                     |

界面使用团队、空间和北极九章工作区。第三方工作区必须带产品名，例如 Slack 工作区、Power BI 工作区。Community 产品名为 Bowra，包名和 `BOWHEAD_*` 配置名保持不变。

北极九章工作区按会话覆盖、用户默认值、唯一可访问工作区的顺序解析。不得从 Bowra 空间推导。连接只能通过当前团队的连接注册表解析，不使用部署、环境变量、成员或默认空间兜底。

## 共享对象

用户通过成员关系加入团队，再通过空间成员关系和资源授权访问空间。会话包含轮次、事件、工具调用、审批与引用。智能体定义行为和资源范围，工具执行操作，技能封装方法、参考资料、模板与脚本。选中资源不等于获得使用权限。

Artifact 是上传文件、工具输出、交付件、导出件与页面捕获的统一身份；文件管理展示这些记录。Canvas 包含区块与修订。分享面向已登录的团队成员，不会匿名公开。

| 前缀                                | 含义                                           |

| `plan_`、`ps_`、`apr_`              | 计划、计划步骤、审批。                         |

保留 `workspace:{id}`、`X-Workspace-Id`、`kb_ws_*` 和已存储的 `workspace_id` 字段。外部北极九章上下文统一使用 `datarc_workspace_id`。不得给现有前缀赋予新含义。

## 不变量

1. 实时显示、持久化数据与回放保持一致。
2. 使用时检查团队成员关系与资源授权；知道 ID 不等于有权访问。
3. 执行、审批与定时任务保留当时的数据上下文快照。
4. 文件功能扩展 Artifact 记录，不另建文件身份体系。
5. 用户和团队技能内容保持隔离，上传内容不得变成全局同名内置技能。
6. 团队定义与术语修改走团队可见的审批路径；个人偏好和单轮指令不得覆盖。
7. 出站 URL 策略由 `BOWHEAD_DEPLOYMENT_MODE` 决定：`local` 支持内网 HTTP 与非标准端口；`saas` 要求公共 HTTPS，并阻止私有／保留地址和受限端口。

修改命名边界或连接解析后，运行 `packages/bowhead_core/tests/test_workspace_datarc_namespace_guard.py`。

Coach 提案审阅将相关 Agent 变更或建议用例归为一组。Owner 可展开审阅以查看差异或选择单项。采纳用例不会运行评估或发布 Agent；Coach 直接写入已有草稿时保留原始回执，无需再次采纳。
