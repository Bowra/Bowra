# 和 Coach 一起改进智能体

你负责的智能体总在某件事上出错时，用自己的话告诉 Coach。Coach 把它写成一条评测要点，拿几条真实回答和你核对它是否按你的意思来判断，然后修改智能体的草稿，并告诉你改动有没有用。你不用自己写要点，只需要说 Coach 对每条回答判得对不对。

## 开始

1. 打开一个 **@Coach** 对话，或在智能体「待处理」列表里某条成员点踩上选择「用它来改进智能体」。
2. 说哪里不好，例如：「它从来不说数字是哪个时间段的」。Coach 会用一句话复述成一条要点，并给出核对卡片。

成员点了踩但没有留言时，Coach 会先问你这条回答哪里不好。智能体还没有任何回答时，Coach 根据智能体的说明起草要点，你照常确认；指定了工具的要点确认后立即生效；这样起草的判断或数据类要点，在真实回答上核对之前仅供参考。

## 不用逐条勾选也能采纳建议

Coach 对已有 Agent 的修改已经保存在草稿里，可在「配置」查看并按需撤销，不必再采纳一次。

「配置」里若有待处理提案，先看目的与影响字段，再点「将这组修改保存到草稿」。需要查看差异或只采用部分内容时，再展开「查看或调整修改」。

建议用例先展示问题和已有的答案标准，点「加入这组用例」即可加入待处理的这一组；需要逐条编辑或选择时，再展开「查看或调整用例」。加入用例不会运行测试，也不会发布 Agent。评测组已经变化时，需让 Coach 根据当前版本重新审视建议。

也可以让 Coach 修改已保存用例。建议会标明「修改已有用例」，整组点「更新」；同时包含新增用例时点「保存这些用例变更」。展开「查看或调整用例」可对照原内容和建议内容。采纳保留同一用例及其历史，不启动评测；删除仍在「评测」页处理。

评测组正在加载时，暂时不能保存建议；加载失败时点「重试」，已有建议和编辑会保留。读取失败不代表评测组已变更。若已无法访问，请联系智能体负责人检查权限，再重新加载页面。

新保存的用例建议也会在聊天里显示简短回执。「审阅建议」进入「配置」页原有待处理区域；已采纳或已忽略的建议显示实际决定，并可「查看当前用例」，进入「评测」页。打开回执或点击入口不会采纳建议、运行测试。原建议与今天保存的用例可能不同。

在结果视图展开「查看原修改」，可读到原问题和已有答案标准摘录，采纳或忽略后也能查看。缺失、截断或省略的内容会明确说明。摘录与当前用例分开，不增加一次审阅步骤。

历史运行保留当时的问题和判断要点。内容已变化时，旧成绩不能验证新内容；重新保存相同内容后，旧证据仍可能有参考价值，但不代表又跑过一次。只读到部分历史，不能证明没有匹配记录，也不能汇总所有历史回答的评分。

## 重新打开最近的操作

在同一段对话里，可以让 **@Coach** 打开最近的操作，例如“打开刚才采纳的那次用例修改”。Coach 请求展示原来保存的结果。若结果到达时你正在编辑，或已经主动选择其他对象，它会保留在成果中，不覆盖你的工作；打开不会另存一次修改、运行测试或发布智能体。

多次操作都可能匹配时，Coach 可能会问你指哪一次。较早或已不可用的记录可能无法从对话恢复，可以到智能体原页面和已有历史里查看可用记录；当前访问权限仍然适用。

读取或保存用例内容不会运行评测。“这次操作没有启动测试”不代表评测组从未运行过；需要历史成绩时，可以询问 Coach 已记录的结果，或在「评测」中查看。

## 管理测试用例

评测组结果统计「运行这组评测」或「保存并运行」发起的运行；「测试这次修改」用于版本比较，结果仍在「发布」页。即使用例后来修改过，旧回答仍对应当时的问题和预期。

在「评测」页，点已保存用例旁的「编辑问题」即可修改。「保存并运行」会先保存当前用例，再运行刚保存的版本；「保存效果测试」只保存，不启动运行。保存失败不会启动；保存后未确认运行结果时，再次运行会恢复同一请求。Agent 版本发生变化时，请先核对更新后的评测对象。

「执行通过」说明执行检查通过，需另看「答案预期」：未评分或部分评分会明确显示，模型判断仅供参考。点「查看回答与评分」，再展开用例，可读到该次记录的问题、回答和预期，通过的用例也能查看。评分校验不一致不代表 Agent 答错。

简短回答也可以评分，无需为凑长度添加解释。历史结果保留当时的评分，需要新的判断时重新运行测试。

自动重跑默认收在结果下方，需要时展开；「与 Coach 核对基线」沿用现有的回答核对对话，不要求每天人工检查。

在 **评测** 页可以移除任意用例，包括最后一个，再选择 **保存效果测试**。保存空用例后，后续测试不再包含这组自定义用例，历史结果仍然保留。你可以随时重新添加用例。已移除的评测组不能单独运行，**测试这次修改** 仍会执行基础安全检查。

没有自定义用例不会阻止发布，也不需要填写接受理由。页面及共享智能体的审批详情会说明回答质量尚未评测。其他安全检查、实际测试失败和共享智能体审批仍按原规则处理。

## 核对 Coach 的判断

核对卡片列出几条回答。每行有问题、回答摘录（Coach 依据的那句会高亮）和 Coach 的结论。

- Coach 判对了的行不用动。
- Coach 判错了选「判错了」，说不清选「说不清」。
- 最后按「其余都判对了」。全部判对时，只需要这一次点击。

每张卡片里有一条是 Coach 把回答改掉要点要求的内容后得到的，标着「Coach 改出来的」，和其他行一样判断即可。

之后：

- **全部判对**：要点确认，加入智能体的评测组，Coach 开始改草稿。
- **有一条判错了**：Coach 提出一个更清楚的说法，再拿几条回答来核对。新卡片会显示改前和改后的说法；想保留原来的，选「保留原文，再看 2 条」。
- **说不清**：Coach 换一条回答补上。累计三条说不清时，Coach 会请你换个说法。
- Coach 有时会单独再问某一行；在那一行选好后按「保存」。

提交卡片后，卡片会给 Coach 发一条简短的 **@Coach** 消息，说明结果，Coach 在同一段对话里接着做。收起后的卡片会说明这条要点进行到哪一步、接下来做什么，例如“要点已确认。下一步：Coach 会按它建议评测用例”。如果你正在输入自己的消息，草稿会保留，卡片提供“发给 Coach”，准备好后点一下即可发送那条消息。之后在这段对话里直接 **@Coach** 也可以，它会接上你们正在进行的核对。

想自己改要点的说法，在卡片上选「改写要点」。改写后卡片重新开始，确认之前不会写入评测组。卡片提示已过期时，说明要点在别处改过，选「重新核对」。

只有智能体的负责人能回答核对卡片，其他人打开这段对话只会看到一行说明。

## 看结果

Coach 改完草稿、跑完检查后，会给出一张检查结果卡片：

- **你说的问题**：含这条要点的用例，改动前后各有几条做到了。
- **Coach 没看过的题**：留出用例（见下文）改动前后的结果。
- **其他变差的**：以前通过、现在不通过的其他用例。选「修好变差的那条」让 Coach 去修。
- 两条新回答，供你读一读。

用例少于 3 条时只显示条数，不显示百分比。检查期间团队的评测模型换了时，卡片会说明这次结果不算；选「用当前评测模型重跑」，再让 Coach 跑一次检查。

## 留出用例

Coach 为一条要点加用例时，会留出其中一条。Coach 看不到留出用例的问题和回答，只知道它通过没有。改动在留出用例上也通过，才说明智能体真的变好了，而不只是答对了 Coach 看过的题。

在智能体的「评测」页签，每条用例都有「留出」开关，开关下写着「Coach 看不到这条，用来检验改动是不是真有效。」，旁边的问号可以打开详细说明。你可以：

- 打开同一条要点的另一条用例，留出会移到那条上。
- 关掉。如果这是该要点唯一的留出用例，会先请你确认；之后 Coach 的报告会写明这次改动无法独立检验。

只有你（负责人）能改留出，Coach 不能。保存评测组后生效。发布检查始终跑全部用例，不管是否留出。

测试始终使用每个启用评测组最新保存的版本：保存评测组、确认要点或接受建议用例后，下一次测试就会包含它们。测试完成后又保存了用例时，结果会标成“结果已过期”，点 **重新测试** 即可把新用例纳入。之前的结果保留在历史中。共享智能体已提交审批时，审核人按提交时的用例审批；审批期间保存的用例从下一次测试开始检查。若想先检查这些用例，请撤回提交后重新测试。

## 测试这次修改

在“评测”或“发布”页点 **测试这次修改**，一步完成：用你最新保存的草稿，和已发布的版本跑同一批用例。配置页还有没保存的修改时，页面会提醒这些修改不会包含在这次测试里。测试运行时可以离开这一页，结果出来后会通知你；需要时可以点 **停止测试**。

- **测试通过**：点 **发布为 v2**（共享智能体为 **提交审批（发布为 v2）**），在对话框里可以写发布说明，它会出现在版本历史里；共享智能体的说明审批人也能看到。
- **有用例变差**：结果会列出变差的用例和没做到的要点，可以点 **让 Coach 修**，或到配置页修改后重新测试。
- **有必需用例没通过**：没有用例变差，但有必需用例在这次修改上没通过（常见情况是已发布版本也没通过）。页面会这样写明，选 **查看没通过的用例** 看回答和没做到的要点，修好后重新测试。
- **没能运行**：页面会写明原因和修法，例如评估模型暂时不可用、测试超出了时间上限；处理后点 **重新测试**。超时时会列出超时的用例，可以把它们拆成更小的任务；某次运行超时只去掉这一次，同一条用例其他跑完的结果照常算数。如果是用例要求的工具在评测里还不能运行，页面会写出是哪个工具、哪几条用例，重新测试也不会变，可以先把这条要点改成「判断标准」。查询数据（例如「查询数据」）目前在评测里也还不能运行：回答要用到它时，页面会说明这条用例在评测里测不了，并写出是哪个工具、哪几条用例。这类用例不算没通过，也不计入变好、持平或变差，重新测试也不会变。
- **数据用例读取北极九章实时数据**：除非部署管理员关闭了评测实时读数，评测里的数据查询（**查询数据**、**查看数据字段**、**确认数据口径**）默认读取团队真实的北极九章数据，不再跳过，数据用例也能得到正常结果。读取时使用 Agent 所有者的北极九章权限，而且只读不改：数据只留在这次测试里，不会保存成数据条目或文件。只有 Agent 的所有者能发起这种测试；如果由其他人发起，数据用例会停下，并提示请所有者来发起。卡片上会写一次用的是谁的权限，因为权限不同的成员看到的数据可能不同。因为是实时数据，如果测试期间两个版本读到的数据变了，这条用例不做比较：页面会写「数据在测试期间变化」，你可以点 **重新测试**。如果问题出在北极九章本身，页面会写明原因和修法：团队没有北极九章连接或连接密钥被拒绝（团队管理员会看到 **打开数据源设置**）、邮箱还没验证、还没选北极九章工作区、你的账号不是该北极九章工作区的成员、你的北极九章账号读不到用例需要的数据，或者北极九章连不上、太忙、查询太慢。只有最后三种会提供 **重新测试**。数据用例超出时限时页面也会说明，可以把时限调长或把用例拆开。你的回答页还会显示每次运行调用北极九章的次数和读取的行数。
- **有用例在得出结果前停止**：每条原因都写了受影响的用例和处理方法。可能是评估模型调用失败或没有设置；Agent 使用的模型被限流、超时、暂时不可用，或拒绝了访问凭据或请求；某个工具出错（页面会写出是哪个工具）；运行被中止（例如服务重启）；或是平台错误，这时会给出一个诊断编号，发给团队管理员即可。如果原因是没有可用模型或凭据被拒，重新测试也会得到同样的结果：团队管理员会看到 **打开模型设置**，其他人会被提示联系管理员；修好后可以点 **修好后重新测试**。
- **评测用不了模型**：如果团队没有给 Agent 的主模型或评估模型设置可用的模型，测试会在开始前被拒绝，页面会写明缺的是哪一个。在 **团队设置 › 模型 › 模型分工** 设置后再测试。
- **发布被拒绝**：如果测试之后有东西变了（草稿、已发布版本或测试本身），或共享智能体还有风险需要你写明理由，发布对话框会说明是哪一项、该怎么做。
- **查看用例的回答**：每次运行的回答会像对话里一样排版（标题、表格）。没通过的运行会列出每条没做到的要点和原因，例如“没有调用「运行代码」”，以及其他没通过的检查。
- **结果已过期**：测试之后草稿又改了，或已发布版本变了，只需点 **重新测试**。
- **只有基础安全检查**：还没有你自己的用例时，测试只能确认它不越界，建议先点 **添加用例** 加几条你关心的问题；保存后卡片会马上更新。不加用例也可以直接 **测试这次修改**。

Coach 改完草稿后自动开始的检查，也显示同一个“测试中”状态，并注明“Coach 改完后自动开始”。

### 发布只有你用的智能体

只有你能用的智能体，测试只是告诉你这次修改的表现，不会拦着你发布。不管测试通过、没有结论、没能运行，还是还没测试，结果旁边都有 **发布为 v2**，也不需要写理由。发布对话框会用一句话说明测试的情况，例如“这次修改的测试没有结论：1 个用例结果不稳定”或“还没测试这次修改”。发布说明照常选填。

- 如果有必需用例变差了，或者没通过「安全执行契约」检查，对话框会直接写明，按钮变成 **仍然发布为 v2**。
- 测试运行中时，先停止测试或等结果出来再发布。
- 版本历史会记下发布时测试的情况，例如“发布时，测试没有结论”。
- 分享给别人用的智能体仍然要审批：测试没有结论时，要重新测试后再提交。

**结果不稳定。** 每条用例会在两个版本上各跑几次，通常是 3 次。结果按多数次来定：3 次里 2 次通过，这条用例就算通过；只有 1 次通过，就算没通过。在 **对比详情** 里仍能看到这几次的情况，例如“这次修改 3 次里 2 次通过、1 次没通过；v1 3 次都通过”。只有几次结果凑不成多数时，这条用例才算结果不稳定，例如 1 次通过、1 次没通过、1 次超时。这时测试没有结论，哪怕只有这一条，结果里会写出这条用例以及它在两个版本上各跑了几次、通过几次。标为 **关键用例** 的（安全执行契约检查）要求更严：每次都必须通过，只要有一次不一致，测试就没有结论。点 **查看回答** 对比回答。重新测试常常就有结论；如果一直不稳定，可以把它的要点写得更具体。

## 要点的来源和 Coach 的建议

在「评测」页签，和 Coach 一起确认的要点会显示它来自你的哪句话、核对过几条回答，选「查看」看明细。从成员点踩开始的要点只显示「来自成员反馈」，不显示成员的留言。

你添加或修改要点后，Coach 会看一遍，只有发现问题时才在要点下方写一行：太笼统判断不了、一条里有两件事、写进了某次回答里的数字，或者和另一条重复或矛盾。选「用这个改写」采用建议，一条里有两件事时选「拆成两条」把它换成两条要点，或选「保留原文」，这段文字就不会再提。评测组也可能显示「Coach 看了整组」，列出没覆盖到的情况和问的是同一件事的用例；选「并排查看」对照这两条用例，可以都保留或删掉其中一条，保存评测组后生效。

要点的「⋯」菜单里有「在回答上核对」，请 Coach 在真实回答上和你一起核对这条要点；已保存的要点还有「查看校准」，列出校准用的样例、每条应该和实际判成什么，以及所用的评测模型。这些都只是建议，不会拦保存或发布；Coach 不可用时什么也不显示。
