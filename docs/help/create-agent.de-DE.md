# Einen eigenen Agent erstellen und verwalten

Sie können einen Agent für sich selbst erstellen, seine Konfiguration prüfen und die Erstellung bestätigen. Anschließend können Sie ihn auf seiner Verwaltungsseite anpassen und verwenden. Die Einstiegspunkte und Optionen hängen davon ab, welche Funktionen Ihr Team aktiviert hat. Dieser Leitfaden beschreibt deshalb die jeweiligen Möglichkeiten so, wie sie auf der Seite angezeigt werden. Wenn eine Option nicht angeboten wird, richten Sie sich nach den tatsächlich angezeigten Möglichkeiten.

## Erstellungsweg auswählen

- **Erstellungsbereich rechts**: **Agenten erstellen** im Agent-Marktplatz oder auf der Verwaltungsseite öffnet rechts neben Ihrer aktuellen Arbeit einen Erstellungsbereich. Unterhaltung und Eingabe bleiben links. Auf schmalen Bildschirmen wechseln Sie zwischen Chat und Erstellungsbereich.
- **Assistant im Chat fragen**: Sagen Sie im Chat, dass Sie einen neuen Agenten möchten, und beschreiben Sie, womit er arbeitet, was er tut und was er liefern soll. Ist der Zweck noch zu ungenau, fragt der Assistant einmal nach. Sie können jederzeit sagen, dass Sie lieber manuell konfigurieren oder abbrechen möchten. Sobald der Zweck klar ist, öffnet sich rechts ein KI-Entwurf; einen ausdrücklich genannten Namen übernimmt er.
- **Entwurf mit KI**: Beschreiben Sie im Bereich rechts das zu lösende Problem. Lassen Sie die KI einen Entwurf erstellen, prüfen Sie ihn und bestätigen Sie die Erstellung. Sie können auch selbst zum Formular wechseln. Kann gerade kein Entwurf erstellt werden, wechseln Sie zur manuellen Konfiguration; der beschriebene Zweck wird übernommen.

Bei jedem Erstellungsweg prüfen Sie die Konfiguration und bestätigen die Erstellung selbst.

## Konfiguration ausfüllen

Geben Sie auf der Erstellungskarte Name, Zweck und Arbeitsanweisungen ein. Wählen Sie anschließend Tools aus den auf der Seite angebotenen Optionen. Skills können Sie nur auswählen, wenn die Seite sie ausdrücklich anbietet. Im letzten Schritt werden die ausgewählten Tools aufgelistet und die Risikokategorie der Team-Tools angezeigt. Prüfen Sie diese Angaben vor der Bestätigung. Bei der Verwendung des Agents werden weiterhin die Berechtigungen der Person und der Verbindungsstatus geprüft.

- Passt kein Tool, können Teams, die textbasierte Assistenten erstellen dürfen, Tools und Skills leer lassen. Andere Teams müssen mindestens ein Tool auswählen. Siehe die Abschnitte zu textbasierten Assistenten unter [Agent-Funktionen konfigurieren](permissions/configure-capabilities.de-DE.md).
- Wählen Sie nur die Skills aus, die der Agent tatsächlich benötigt. Ein hinzugefügter Skill kann gelesen werden; enthält er Skripte, darf der Agent sie auch in der isolierten Sandbox ausführen. Eigene Tools zum Lesen, Ausführen oder Auflisten von Skills wählen Sie nicht aus. Hat die Bereitstellung Skill-Skripte nicht aktiviert, weist der Editor beim Skill darauf hin: Der Agent kann ihn lesen, die Skripte aber erst nach Aktivierung durch die Administration ausführen; danach müssen Sie nicht erneut speichern. Ein bereits veröffentlichter Agent behält seine Berechtigungen, bis Sie ihn erneut veröffentlichen. Skills gewähren keinen Zugriff auf Daten oder Verbindungen.
- Der Agent verwendet jeweils die neueste genehmigte Version eines Skills. Wurde ein verwendeter Skill aktualisiert, zeigen die Agent-Seite und die Release-Prüfung das an und empfehlen eine erneute Evaluierung. Schalten Sie einen Team-Skill unter Skills nur für sich aus, betrifft das keine Agents, die ihn enthalten; eine Einschränkung durch die Teamadministration gilt weiterhin.
- Ist das Speichern oder Veröffentlichen blockiert, nennt die Meldung jeden betroffenen Skill oder jedes Tool mit Grund und Abhilfe. Bei **Bearbeitet und wartet auf erneute Genehmigung** oder **Noch nicht genehmigt** bitten Sie die Teamadministration um Genehmigung oder entfernen den Skill. Bei **Für das Team deaktiviert** bitten Sie um erneute Aktivierung. Sind **die Dateien nicht lesbar** oder fehlt **der Sicherheitsprüfungseintrag** oder ist er beschädigt, laden Sie den Skill erneut hoch. Gehört **der Name jetzt zu einem anderen Skill** oder hat er sich **nach dem Hinzufügen geändert**, entfernen Sie ihn und fügen ihn erneut hinzu. **Mitgelieferte eigene Pakete** prüft die Teamadministration vor der Veröffentlichung. Erwähnt die Anleitung eines Skills Befehle wie `curl`, erscheint in der Release-Prüfung nur ein Hinweis; Skripte laufen ohne Netzwerkzugriff.
- Kann ein Skill während eines Laufs nicht verwendet werden, nennt der Schritt den Skill, die versuchte Aktion und den Grund, etwa nicht aktivierte Skill-Skripte, eine Einschränkung durch die Teamadministration, eine ausstehende erneute Genehmigung oder einen nicht mehr vorhandenen Skill. Folgen Sie dem Hinweis; dieselbe Anfrage zu wiederholen hilft erst, wenn die Ursache behoben ist.
- Im Schritt Tools können Sie ganze Plugins auswählen: integrierte Plugins (etwa Datenanalyse oder Berichte und Canvas) und Team-Plugins erscheinen dort mit ihrer Versionsnummer. Ein Plugin bringt seine Tools mit; ein Plugin mit Richtlinien hängt diese automatisch an. Ist ein Plugin nicht auswählbar, steht der Grund dabei, etwa „Von Ihrem Team deaktiviert“, „Nicht bereit“ oder „Verfügbar, sobald die Bestätigung pro Aufruf bereit ist“. Ein ausgewähltes Plugin, das später nicht mehr verfügbar ist, bleibt ausgewählt, damit Sie es abwählen können. Wird ein Plugin aktualisiert, nutzt der Agent beim nächsten Lauf den neuen Inhalt.
- Beim Prüfen eines KI-Entwurfs können Sie Plugins und Skills an derselben Stelle hinzufügen oder entfernen. Beim Bearbeiten eines vorhandenen Agents (auch über den Konfigurationsassistenten) passen Sie seine Plugins an; gespeichert werden nur geänderte Auswahlen.
- Soll der Agent später Webseiten prüfen, die Sie ihm geben, reicht bei der Erstellung der Hinweis „Die URL wird jedes Mal von der nutzenden Person angegeben“. Sie müssen keinen Link aus einer bestimmten Aufgabe eintragen. Prüfen Sie, ob der Entwurf die Fähigkeit zum Lesen von Webseiten enthält. Eine Websuche findet andere Seiten und ersetzt nicht das Lesen eines konkreten Links. Kann eine Seite beim Ausführen nicht gelesen werden, meldet der Agent, dass er sie diesmal nicht prüfen konnte. Kontrollieren Sie dann die Erreichbarkeit des Links oder fügen Sie den Seiteninhalt ein und versuchen Sie es erneut.
- Erfordert der Zweck Geschäftsdaten des Teams, zum Beispiel Ladenumsätze oder Verkaufsdetails, wählt der Entwurf das integrierte Tool für Datenabfragen aus, auch wenn die Beschreibung nur „Teamdaten“ nennt.
- Fehlt bei einer erforderlichen Funktion ein ausgewähltes Tool, schlägt die Konfigurationsprüfung fehl. Sie erklärt, welche Funktion fehlt, warum nichts ausgewählt wurde und wie Sie den Fehler beheben: Wählen Sie wie angegeben ein passendes Tool aus der Liste. Ist das Tool gesperrt, bitten Sie eine Teamadministration, es zu aktivieren. Bis zur Behebung können Sie den Agent nicht erstellen.
- Ist ein Tool oder Skill beim Speichern nicht mehr verfügbar, behält die Karte Ihre Eingaben bei und fordert Sie auf, zurückzugehen und die Ressource zu prüfen, zu entfernen oder zu ersetzen.

Ein neuer Agent ist nur für Sie sichtbar. Er wird nicht automatisch mit Kolleginnen und Kollegen geteilt und erscheint nicht im Agent-Marktplatz. Informationen zum Teilen finden Sie unter den verfügbaren Freigabeaktionen auf seiner Verwaltungsseite.

In Bowra Community erscheint ein erfolgreich erstelltes Dokument als herunterladbare Datei in der Unterhaltung. Ein Dateiname in einer Antwort bestätigt noch keine erstellte Datei. Fordern Sie für PowerPoint eine neue einfache Präsentation mit Text und Tabellen an. Wenn eine hochgeladene Vorlage erhalten bleiben soll, muss der Agent die Einschränkung erklären und vor der Erstellung fragen, ob eine separate neue Präsentation akzeptabel ist. Prüfen Sie die heruntergeladene Datei vor dem Teilen; dieser Skill bietet weder eine Folienvorschau noch eine originalgetreue Übernahme der Vorlage.

## Entwürfe speichern und später fortsetzen

Im Erstellungsbereich rechts wird bei manueller Erstellung zunächst ein Entwurf angelegt und anschließend das Formular angezeigt. Auch beim Entwurf mit KI wird ein Entwurf erstellt, den Sie später fortsetzen können. Kann die Seite den Entwurf nicht anlegen, wählen Sie **Entwurf erneut erstellen**. Der erneute Versuch setzt dieselbe Erstellungsaufgabe fort.

- Nachdem Sie eine Eingabe unterbrochen haben, werden Änderungen automatisch gespeichert. Sie können auch **Entwurf speichern** auswählen. Änderungen sind erst gespeichert, wenn die Meldung **Entwurf gespeichert** erscheint. Schlägt das automatische Speichern fehl, bleiben Ihre Eingaben im Bereich erhalten. Versuchen Sie das Speichern wie aufgefordert erneut.
- Der Entwurf im Canvas wird automatisch gespeichert; die Werkzeugleiste zeigt **Gespeichert** oder **Wird gespeichert**. Nur solange noch gespeichert wird oder das Speichern fehlgeschlagen ist, fragt das Schließen oder der Wechsel von Seite, Unterhaltung oder Bereich nach **Weiter bearbeiten** oder **Ungespeicherte Änderungen verwerfen**. Beim Verwerfen werden nur ungespeicherte Änderungen verworfen; der gespeicherte Entwurf bleibt erhalten. Schlägt das Speichern fehl, wählen Sie in der Werkzeugleiste **Erneut versuchen**.
- Hat ein anderer Browser-Tab denselben Entwurf zuerst gespeichert, zeigt die Seite für jedes Feld den Wert vor der Bearbeitung, Ihre Eingabe und den neuesten gespeicherten Wert. Entscheiden Sie für jedes Feld und speichern Sie anschließend. So überschreiben Sie keine Änderungen aus dem anderen Tab.
- Über den allgemeinen Erstellungsbereich können Sie einen unvollständigen Entwurf im aktuellen Bereich fortsetzen oder ausdrücklich einen neuen beginnen. Die Entwurfsliste zeigt Name, Quelle, Status, Zeitpunkt der letzten Speicherung und Ablaufdatum. So können Sie die Entwürfe unterscheiden. Wenn Sie einen manuellen Entwurf fortsetzen, öffnet sich direkt der manuelle Editor rechts.
- Unter **Von mir erstellt** finden Sie bei Ihren Agents ebenfalls unvollständige KI- und manuelle Entwürfe, die fortgesetzt werden können. Ist ein Entwurf geöffnet, können Sie seine Adresse zum Aktualisieren der Seite verwenden und ihn weiter anzeigen.
- Wird der Entwurf nicht gefunden, prüfen Sie den aktuellen Bereich, wählen Sie **Meine Entwürfe anzeigen**, um andere Entwürfe zu finden, oder beginnen Sie erneut. Abgelaufene Entwürfe können nicht fortgesetzt werden. Schlägt das Laden vorübergehend fehl, versuchen Sie es über die Karte erneut.

## Mit KI einen Entwurf erstellen

1. Wählen Sie den KI-Entwurf, geben Sie das Ziel ein und lassen Sie Vorschläge erstellen. Während die Vorschläge entstehen, können Sie die Wartezeit abbrechen und selbst Felder ausfüllen. Die Ergebnisse erscheinen später im selben Entwurf.
2. Vergleichen Sie den aktuellen Inhalt Feld für Feld mit den KI-Vorschlägen. Übernehmen Sie nur die gewünschten Felder oder ignorieren Sie einen Vorschlag vollständig. Ihre eigenen Änderungen werden niemals automatisch ersetzt. Benötigt die KI weitere Informationen, antworten Sie rechts oder ändern Sie das Ziel und erstellen Sie neue Vorschläge.
3. Passen die empfohlenen Tools nicht zu Ihrer Aufgabe, öffnen Sie unter **Fähigkeiten und Tools** den Tool-Katalog. Suchen Sie dort nach anderen Tools, die Sie verwenden dürfen, und wählen Sie sie aus oder entfernen Sie die ursprünglichen Vorschläge. Die Seite kennzeichnet hinzugefügte Tools und erklärt, warum bestimmte Tools nicht ausgewählt werden können. Wenn Sie fertig sind, wählen Sie **Speichern und prüfen**. Kann der Katalog nicht geöffnet werden, bleiben Ihre Eingaben und Auswahlen erhalten; versuchen Sie es später erneut. Meldet das Speichern, dass ein Tool nicht mehr verfügbar ist, entfernen oder ersetzen Sie es wie angegeben. Ob Sie hier Skills hinzufügen können, hängt von den angebotenen Optionen ab.
4. Prüfen und bestätigen Sie die Erstellung.

Um das Formular selbst auszufüllen, wählen Sie **Manuell konfigurieren**. Änderungen, die Sie rechts vorgenommen haben, werden im selben Entwurf gespeichert. Das ursprüngliche Ziel wird mit einer Kurzfassung in der Routing-Beschreibung in die Arbeitsanweisungen übernommen; ein im Chat ausdrücklich genannter Name bleibt erhalten. Nach dem Wechsel können Sie den Entwurf weiterhin über die ursprüngliche Adresse oder unter **Von mir erstellt** fortsetzen. Wird ein Versionskonflikt gemeldet, prüfen Sie die Angaben und laden Sie die Seite zuerst neu. Schlägt eine Anfrage fehl, prüft die Seite den Status des Entwurfs erneut. Kann er nicht mehr erstellt werden, wechseln Sie zur manuellen Konfiguration; das ursprüngliche Ziel und zusätzliche Antworten werden übernommen. Wenn Sie Name oder Arbeitsanweisungen ändern, werden die ursprünglichen Begründungen für empfohlene Tools nicht gelöscht.

## Einen Entwurf im Chat bearbeiten

Wenn Ihr Team Chat-Bearbeitung von Entwürfen anbietet, sind geprüfte KI-Entwürfe und gespeicherte manuelle Entwürfe mit dem aktuellen Chat verbunden. Zeigt die rechte Seite an, dass der Entwurf mit diesem Chat verbunden ist, beschreiben Sie links die zu ändernden Felder. Nach dem Speichern wird die rechte Seite aktualisiert; dort prüfen und bestätigen Sie die Erstellung. Fordert die rechte Seite Sie zum Bearbeiten auf, nehmen Sie die Änderungen direkt dort vor.

- Gibt es rechts ungespeicherte Änderungen, bleibt eine neue Nachricht im Composer. Sie werden daran erinnert, zuerst rechts zu speichern oder die Änderungen zu verwerfen. Senden Sie die Nachricht danach erneut.
- Änderungen aus dem Chat überschreiben nie Ihre laufende Eingabe. Bei einem Versionskonflikt laden Sie die Seite wie aufgefordert neu.
- Eine manuelle Karte ohne Chat-Verbindung muss rechts bearbeitet werden. Antworten links ändern sie nicht.

## Nach der Erstellung

Nach dem Erstellen des Agents wählen Sie **Agent verwalten**, um ihn direkt zu öffnen und die Konfiguration zu prüfen oder anzupassen. Sie können ihn später auch unter Ihren Agents finden. Dass er zu Ihrer persönlichen Liste hinzugefügt wurde, bedeutet nicht, dass Sie ihn eingestellt haben. Ältere Agents öffnen ihre ursprüngliche Konfigurationsseite; Agents mit Versionsverwaltung öffnen die Versionsarbeitsfläche.

Die Versionsarbeitsfläche hat drei Tabs: **Konfigurieren**, **Evaluieren** und **Veröffentlichen**; angezeigt werden nur die Tabs, die Ihr Team aktiviert hat. Die früheren Tabs für Änderungsvorschläge, Prüfung und Veröffentlichung sowie Versionsverlauf sind darin aufgegangen; alte Links führen automatisch an die passende Stelle.

- **Konfigurieren**: eine Seite mit drei einklappbaren Abschnitten. **Was er tut** enthält Name, Beschreibung, Arbeitsanweisungen, integrierte Werkzeugrichtlinien, Modell und Hauptfunktion. **Was er nutzen kann** enthält Plugins, Skills, Tools und Verbindungen; **Hinzufügen…** öffnet den Katalog in einer Seitenleiste. **Wer ihn nutzen kann und wie er gelistet ist** enthält Zielgruppe, optionale Methoden, Angaben im Marktplatz, Kopierrichtlinie und Ausgabevertrag und ist standardmäßig eingeklappt. Blockiert etwas in einem Abschnitt die Veröffentlichung, wird seine Überschrift rot und nennt den Grund. Oben listet **Ausstehende Vorschläge** Änderungen aus externen Pipelines und Nutzerfeedback auf, die Sie prüfen und übernehmen können; der Bereich ist ausgeblendet, wenn nichts aussteht, und der Tab **Konfigurieren** zeigt die Anzahl. Jede Änderung zeigt den aktuellen neben dem vorgeschlagenen Wert; haben Sie seit der letzten Veröffentlichung keinen Entwurf gespeichert, wird mit der veröffentlichten Version verglichen, und das Übernehmen legt den Entwurf daraus an. Ist **Ausgewählte Änderungen übernehmen** nicht verfügbar, nennt die Karte den Grund, etwa wenn keine Änderung ausgewählt ist. Darüber zeigt eine Liste der zu prüfenden Daumen nach unten eine Zeile pro Runde, der ein Mitglied einen Daumen nach unten gegeben und die es zugleich mit Ihnen geteilt hat: die Kennzeichnung **Daumen nach unten**, den Anfang der Frage, darunter wer, wann, die gewählten Gründe und den Kommentar (**Kein Kommentar**, wenn keiner geschrieben wurde). **Damit den Agent verbessern** öffnet eine neue Unterhaltung mit Coach, in der Frage, Gründe und Kommentar im Eingabefeld bereitstehen; gesendet wird erst, wenn Sie senden. **Verwerfen** entfernt den Eintrag, mit Rückgängig. In beiden Fällen verlässt der Eintrag die Liste und zählt nicht mehr für den Tab **Konfigurieren**; die Runde bleibt unter **Aus Unterhaltungen entwerfen** verfügbar. Ein Eintrag verschwindet auch, wenn das Mitglied das Teilen beendet oder den Daumen nach unten zurücknimmt. Einen nicht geteilten Daumen nach unten sehen Sie nie, und eine nur über das Menü **⋯** geteilte Runde ohne Daumen nach unten erscheint nur unter **Aus Unterhaltungen entwerfen**; für diese Einträge gibt es keine Benachrichtigungen im Posteingang.
- **Evaluieren**: Evaluierungssuiten verwalten.
- **Veröffentlichen**: beginnt mit der Karte **Diese Änderung**. Sie listet pro Abschnitt, was sich geändert hat und von wem (Coach, Manuell, Externe Pipeline oder Feedback), dazu die Evaluierungssuiten und den Stand der Freigabeprüfung, jeweils mit einem Link zum passenden Tab. Gibt es keinen Unterschied, meldet sie, dass der Entwurf der Live-Version entspricht. Darunter folgen die Freigabeprüfung und ihre Aktionen, ganz unten der Versionsverlauf mit **Entwurf aus dieser Veröffentlichung erstellen**.
- **Externe Pipelines**: Externe Pipelines werden über Team-OpenAPI-Schlüssel verwaltet, nicht in der Arbeitsfläche; ihre Vorschläge erscheinen unter **Ausstehende Vorschläge** als **Vorschlag einer externen Pipeline**. Um eine externe Pipeline zu stoppen, deaktivieren oder widerrufen Sie ihren Schlüssel unter Teameinstellungen › OpenAPI.

- **Verwenden**: Wird **Verwenden** angeboten, öffnet die Auswahl einen neuen Chat, in dem dieser Agent vorausgewählt ist. Dort geben Sie die Aufgabe ein. Verfügbare Agents auf der Detailseite und in der Verwaltungsliste haben denselben Einstieg. Haben sich die aktuelle Version oder Berechtigungen geändert, fordert die Seite Sie auf, zur Verwaltungsseite zurückzukehren. Ein als Text eingegebener Name gilt nie als ausgewählter Agent. Nicht gesendete Entwürfe bleiben erhalten.
- **Konfiguration ändern**: Passen Sie die Konfiguration auf der Konfigurationsseite an und speichern Sie eine Arbeitskopie. Das Speichern ändert nicht die derzeit verwendete Version. Ein neu erstellter Agent hat bereits eine verwendbare aktuelle Version. Daher gibt es beim ersten Öffnen der Versionsarbeitsfläche möglicherweise noch keinen **Nächsten Entwurf**. Meldet die Seite, dass Änderungen nur im Browser gespeichert sind, speichern Sie sie zuerst und wechseln Sie anschließend zum Tab **Veröffentlichen**.
- **Integrierte Werkzeugrichtlinien**: Aktivieren Sie diese Option unter **Was er tut** im Tab **Konfigurieren** der Versionsarbeitsfläche, wenn der Agent zusätzlich die Richtlinien von Bowra für die Werkzeuge befolgen soll, die er verwenden kann, etwa die Regeln für Abfragen von Geschäftsdaten. Standardmäßig ist sie deaktiviert. Wie andere Einstellungen wirkt sie erst, wenn Sie die Arbeitskopie speichern und die neue Version aktiv ist; Aktivieren oder Deaktivieren erzeugt eine neue Version, die Prüfende als Änderung sehen.
- **Neue Version übernehmen**: Bei einem Agent, den nur Sie verwenden, wählen Sie nach der Prüfung **Neue Version übernehmen**. Die neue Version gilt nur für Sie und wird nicht im Marktplatz aufgeführt. Folgen Sie bei Versionen für Kolleginnen und Kollegen den Anweisungen auf der Seite: **Neue Version aktivieren** ändert die aktuelle Version und die Sichtbarkeit. Das ist nicht dasselbe wie eine Veröffentlichung im Marktplatz, der derzeit Agents entsprechend ihrer Teamsichtbarkeit anzeigt. Ist eine Freigabe erforderlich, wird **Zur Administratorfreigabe einreichen** angezeigt. Prüfen Sie zuvor Zielgruppe und Auswirkungen. Siehe [Agent veröffentlichen](permissions/publish-agent.de-DE.md).
- **Wer ihn nutzen kann und wie er gelistet ist**: Dieser eingeklappte Abschnitt im Tab **Konfigurieren** legt Zielgruppe, optionale Methoden, Angaben im Marktplatz wie Beschreibung und Kategorie, Kopierrichtlinie und Ausgabevertrag fest.
- **Evaluierungen**: Wird der Tab **Evaluieren** angeboten und lautet ein Ergebnis **Fehlgeschlagen** oder **Unvollständig**, wählen Sie **Grund anzeigen**. Meldet die Seite einen Fehler in der Evaluierungsumgebung, sagt das Ergebnis nichts über die Qualität des Agents aus. Versuchen Sie es später erneut und wenden Sie sich bei anhaltenden Problemen an die Administration. Fehlgeschlagene Testfälle sollten Sie veranlassen, Aufgabe und erwartetes Ergebnis zu prüfen. Schließen Sie nicht allein daraus, dass die Konfiguration falsch ist, dass kein einziger Fall bestanden wurde. Meldet die Seite eine aktualisierte Evaluierungsrichtlinie, aktualisieren Sie die Seite, prüfen Sie den aktuellen Testplan und bereiten Sie die Evaluierung erneut vor. Die Seite prüft gegen die aktuelle Richtlinie und überschreibt keine gerade vorgenommenen Änderungen.
- **Erwartete Punkte in Ergebnissen**: Öffnen Sie die Antworten eines Falls, listet jeder Lauf die Punkte des Falls mit **Erfüllt**, **Nicht erfüllt** oder **Nicht bewertet** und dem Satz der Antwort, auf den sich das Urteil stützt; erfüllte Punkte sind unter dem Lauf eingeklappt. Ist ein Urteil in einer der beiden Richtungen falsch, wählen Sie **Falsch bewertet**. Die Antwort wird erfasst, sodass spätere Prüfungen dieses Punkts sie umgekehrt bewerten müssen, und Coach kann eine Umformulierung vorschlagen; das Ergebnis dieses Vergleichs ändert sich nicht. Passen Sie den Punkt an und führen Sie den Vergleich erneut aus. Ein Punkt, der die Prüfung mit guten und schlechten Antworten nicht bestanden hat, wird nur zur Information angezeigt, mit Begründung. Nennt eine Release-Prüfung „Ein vom Modell bewerteter Punkt wurde nicht erfüllt“ als Risiko, stehen die nicht erfüllten Punkte mit ihren Sätzen beim Risiko, jeweils mit **Falsch bewertet**; Sie können das Risiko erfassen und veröffentlichen, das Urteil markieren oder beides.

### Einen bestehenden Agent von Coach ändern lassen

Nennen Sie im Chat einen Agent, dessen Eigentümerin oder Eigentümer Sie sind, und beschreiben Sie die gewünschte Änderung. Sie können auch neben den Tabs der Versionsverwaltung **Coach um Änderung bitten** wählen oder bei einer fehlgeschlagenen Release-Prüfung **Coach beheben lassen**: Ein neuer Chat öffnet sich mit **@Coach** und der Anfrage im Eingabefeld. Gesendet wird erst, wenn Sie die Anfrage ergänzen und absenden. Dürfen Sie diesen Agent bearbeiten (dasselbe Recht, das Sie zum manuellen Speichern seiner Arbeitskopie brauchen), schreibt Coach die Änderung direkt in seinen Entwurf; Sie müssen nichts Feld für Feld übernehmen. Rechts öffnet sich der Editor des Agents. Dürfen Sie den Agent nicht bearbeiten, antwortet Coach nur mit Vorschlägen im Chat und ändert nichts.

Sie können Coach auch selbst ansprechen: Geben Sie im Eingabefeld **@** ein und wählen Sie **Coach**, oder öffnen Sie Coach im Agent-Marktplatz. Andere Anfragen werden Coach nie automatisch zugewiesen. Hat Ihr Team Coach deaktiviert, erscheint Coach an keiner der beiden Stellen.

- Die Änderung landet nur im Entwurf; nichts wird veröffentlicht oder angewendet. Die neue Version gilt erst nach der Freigabeprüfung im Tab **Veröffentlichen**.
- Hat der Canvas ungespeicherte Änderungen, wird Ihre Nachricht nicht an Coach gesendet und über dem Eingabefeld erscheint ein Hinweis: **Speichern und fortfahren** speichert den Canvas und sendet dann dieselbe Nachricht; **Änderungen verwerfen** verwirft die Canvas-Änderungen, danach können Sie erneut senden.
- Jedes Mal, wenn Coach den Entwurf schreibt, zeigt eine Zeile unter der Antwort, wie viele Änderungen im Entwurf gelandet sind; **Im Canvas ansehen** öffnet den Agent.
- Fügt Coach einen Skill hinzu, müssen die von ihm benötigten Skills mitkommen. Fehlen welche, schreibt Coach nichts und nennt die benötigten Skills.
- Nachdem Coach den Entwurf geschrieben hat, wird ein geöffneter Editor dieses Agents aktualisiert, sofern er keine ungespeicherten Eingaben enthält.
- Ist ein Tool oder Skill ungültig oder fehlt Ihnen die Berechtigung, beheben Sie das zuerst unter **Was er nutzen kann**.

Der Agent-Editor im Canvas zeigt von oben nach unten **Änderungen von Coach**, die drei Konfigurationsabschnitte (Was er tut, Was er nutzen kann, Wer ihn nutzen kann und wie er gelistet ist) und die Karte der Freigabeprüfung, auf der Sie eine Prüfung starten und veröffentlichen können.

- Jede Zeile unter **Änderungen von Coach** steht für ein Feld. **Rückgängig** stellt nur wieder her, was Coach geschrieben hat, und berührt Ihre eigenen Änderungen nie; eine rückgängig gemachte Zeile bietet **Erneut anwenden**. **Alle rückgängig** macht alle Zeilen rückgängig.
- Haben Sie ein Feld nach Coach ebenfalls geändert, zeigt seine Zeile **Auch von Ihnen geändert** und **Konflikt ansehen**. Der Dialog zeigt den Wert vor Coach, den von Coach geschriebenen Wert und den aktuellen Wert. Sie können wählen:
  - **In Konfigurieren bearbeiten**: das Feld selbst in der Konfiguration ändern.
  - **Aktuellen Wert behalten**: Ihren Wert behalten. Die Zeile verschwindet aus **Änderungen von Coach** und gilt danach als manuelle Änderung; der Entwurf bleibt unverändert.
  - **Wert vor Coach wiederherstellen**: nach Ihrer Bestätigung ersetzt ein gewöhnliches Speichern Ihren aktuellen Wert durch den Wert vor Coach.
- Solange ein Feld im Konflikt ist, macht **Alle rückgängig** nichts rückgängig und bietet stattdessen **Die anderen N rückgängig machen** an.
- Solange der Canvas ungespeicherte Änderungen hat, warten die Schaltflächen zum Rückgängigmachen, bis Sie speichern oder verwerfen.

#### Nachdem Coach einen Entwurf bearbeitet

Unter **Persönliche Einstellungen → Konto → Agents** oder im Menü **⋯** des Canvas-Editors wählen Sie, was nach einer Bearbeitung durch Coach geschieht. Die Einstellung gilt nur für Änderungen, um die Sie Coach selbst bitten.

- **Automatisch prüfen** (Standard): Nachdem Coach den Entwurf geschrieben hat, startet er eine Freigabeprüfung für diese Änderung mit einem festen Limit von höchstens 200 Modellanfragen, 1 Vergleich und 30 Minuten. Kann die Schätzung 200 Anfragen überschreiten, startet die Prüfung nicht; Sie werden gebeten, sie zu prüfen und selbst zu starten. Eine neuere automatische Prüfung ersetzt eine ältere, die noch läuft, und zieht deren Kandidaten zurück, wenn er nur vorbereitet war. Ein bereits zur Prüfung eingereichter Kandidat wird nie zurückgezogen: Die Prüfung startet dann nicht, und Sie werden gebeten, den Kandidaten im Tab **Veröffentlichen** zurückzuziehen. Bereits verbrauchte Anfragen bleiben angerechnet.
- **Zuerst fragen**: Coach fordert die Prüfung nur an. Prüfen Sie den geschätzten Verbrauch und starten Sie sie über die Karte der Freigabeprüfung.

In beiden Fällen veröffentlicht oder wendet eine bestandene Prüfung den Agent nicht von selbst an.

## Beschreiben, was eine gute Antwort tut

Auf dem Tab **Evaluieren** kann jeder Testfall erwartete Punkte enthalten: einfache Aussagen darüber, was eine gute Antwort tut. Es gibt drei Arten:

- **Beurteilungskriterium**: etwas, das in der Antwort sichtbar ist, etwa „vergleicht mit demselben Monat im Vorjahr“.
- **Datenfakt**: eine Zahl, die die Antwort nennen soll, etwa „nennt den Umsatz in Ostchina im letzten Quartal“. Sie wird mit den Daten verglichen, die der Agent in diesem Lauf tatsächlich gelesen hat.
- **Erforderliche Aktion**: ein Tool, das der Agent vor der Antwort aufrufen muss, etwa eine Abfrage von Verkaufsdaten.

**Testfälle mit KI vorschlagen** entwirft für jeden Fall einige Punkte, und Coach kann Punkte vorschlagen, wenn er Fälle vorschlägt. Ein vorgeschlagener Punkt zeigt seine Herkunft. Er zählt erst, wenn du **Bestätigen** wählst; Punkte, die du selbst schreibst, gelten beim Speichern der Suite als bestätigt. Speichere deine Änderungen anschließend.

Hat die Live-Version die Frage eines Falls bereits beantwortet, wähle unter den Punkten des Falls **Ansehen, wie sie bei der Live-Antwort beurteilt werden**; dann siehst du diese Antwort und wie jeder vorgeschlagene Punkt daran bewertet würde, mit dem Satz, auf den sich die Bewertung stützt. Wirkt eine Bewertung falsch, formuliere den Punkt vor dem Bestätigen um. Wähle **Als gute Antwort markieren**, wenn du die Live-Antwort akzeptieren würdest; das hilft zu prüfen, ob der Punkt gute von schlechten Antworten unterscheidet.

Jeder Punkt zeigt eine Statuszeile. Derzeit blockiert nur eine erforderliche Aktion (ein Punkt mit einem Tool) ein Release und zeigt **Blockiert das Release**; Beurteilungs- und Datenpunkte dienen nur zur Information und sagen das, auch während sie kalibriert werden oder solange die Bewertung dieser Art von Punkt noch validiert wird. Füge mit **Punkt hinzufügen** unter dem Testfall einen Punkt hinzu und bearbeite oder lösche ihn über sein **⋯**-Menü. Tipps: ein Punkt beschreibt genau eine Sache, etwas, das man in der Antwort finden kann, und keine exakten Zahlen aus heutigen Daten, die sich zwischen Läufen ändern.

Um aus einer Beschwerde einen Punkt zu machen, ohne ihn selbst zu schreiben, frag Coach und prüfe seine Urteile an echten Antworten; siehe [Einen Agent mit Coach verbessern](agent-evaluation-with-coach.de-DE.md), dort ist auch der Schalter **Zurückgehalten** jedes Testfalls erklärt.

### Testfälle für die Bewertung erstellen

- **Aus Unterhaltungen entwerfen.** Wählen Sie im Tab **Evaluieren** die Option **Aus Unterhaltungen entwerfen** und markieren Sie bis zu 32 Fragen, die Sie diesem Agent gestellt haben. Jede wird zu einem Testfall mit Ihrer Frage im Wortlaut als Aufgabe, und Coach schlägt vor, was eine gute Antwort enthalten muss. Aufgeführt werden Ihre eigenen abgeschlossenen Unterhaltungen sowie einzelne Runden, die Mitglieder über das Menü **⋯** einer Antwort mit Ihnen geteilt haben, gekennzeichnet mit **Geteilt von** und ihrem Namen. Andere Unterhaltungen der Mitglieder sehen Sie nie, und die Antwort einer geteilten Runde wird erst gelesen, wenn Sie daraus einen Testfall entwerfen. Mitglieder können das Teilen jederzeit beenden; die Runde verschwindet dann aus Ihrer Liste, ein bereits daraus entworfener Testfall ist aber Ihre Kopie und bleibt in Ihrer Testreihe. Prüfen Sie die Entwürfe und speichern Sie dann die Testreihe; ausgeführt wird erst, wenn Sie eine Bewertung starten.
- **Frühere Standardwerte.** Vor dem 15. Oktober 2026 gespeicherte Testfälle erlauben möglicherweise noch keine Tool-Aufrufe und prüfen streng auf erfundene Zahlen, sodass ein Agent, der Daten abfragt, allein deshalb durchfallen kann. Die Testreihe zeigt dann die Anzahl betroffener Testfälle und **Auf aktuelle Standardwerte umstellen**. Dabei wird eine neue Revision gespeichert, die nur diese beiden Einstellungen entfernt; frühere Ergebnisse bleiben unverändert.
- **Eine Freigabeprüfung lesen.** Über den Änderungen pro Testfall zeigt der Tab **Veröffentlichen**, wie viele Testfälle ausgeführt wurden und wie oft die neue und die Live-Version bestanden haben. Hat bei einer Version kein Testfall ein Ergebnis erreicht, etwa weil alle unklar blieben, steht dort „noch kein Ergebnis“.

## Die Beschreibung des Agents übersetzen

Bietet die Verwaltungsseite Übersetzungen der Agent-Beschreibung an, wählen Sie die Originalsprache und eine andere Zielsprache: vereinfachtes Chinesisch, Englisch, Deutsch oder Französisch. Tragen Sie den übersetzten Namen und die Beschreibung selbst ein oder lassen Sie die KI einen Entwurf erstellen. Prüfen Sie den Entwurf, speichern Sie ihn und bestätigen Sie anschließend die Übersetzung. Der bestätigte Text gilt ab der nächsten Veröffentlichung und durchläuft dieselben Prüfungen und Freigaben wie das Original.

Sobald eine Übersetzung vorhanden ist, kann die Originalsprache nicht mehr geändert werden. Ändert sich der Originaltext, prüfen und speichern Sie die Übersetzung erneut, bevor Sie sie bestätigen. Übersetzt werden nur der öffentliche Name und die Beschreibung; Arbeitsanweisungen und Berechtigungen des Agents bleiben gleich. Nur die Eigentümerin oder der Eigentümer des Agents kann seine Übersetzungen verwalten.

## Agent in einem Chat verwenden

Der Lead-Agent bezieht den Agent in die Unterhaltung ein, wenn die Aufgabe dazu passt und aktuelle Berechtigungen sowie Ressourcen es zulassen. **Wenn Sie nur den Namen des Agents in den Composer schreiben, wird die Aufgabe nicht automatisch von ihm übernommen.** Klappen Sie den Ablauf der Antwort auf und prüfen Sie, welche Agents beteiligt waren.

Wenn der Composer Schnellverweise anbietet:

- Geben Sie `@` ein, um für diese Aufgabe einen Agent auszuwählen, oder `/`, um einen Skill auszuwählen. Markieren Sie zuerst die gesamte Eingabe und geben Sie dann `@` oder `/` ein, wird die Eingabe ersetzt und die passende Liste geöffnet. Einfügen dieser Zeichen öffnet die Liste nicht. Wählen Sie nur einen Skill aus, versucht Bowra, einen passenden derzeit verfügbaren Agent zuzuweisen. Prüfen Sie vor dem Senden die ausgewählten Namen und Anhänge.
- Stellt der Agent vor oder während der Bearbeitung eine Rückfrage, antworten Sie auf der Fragekarte im aktuellen Chat. Wurde ein Anhang zurückgezogen oder geändert, senden Sie die Aufgabe erneut. Um Agent oder Skill zu wechseln, senden Sie ebenfalls eine neue Aufgabe.
- Mit Tab wird gewöhnlicher Text aus dem Verlauf vervollständigt. Frühere `@`- und `/`-Namen werden durch Tab nicht als ausgewählte Verweise wiederhergestellt. Wählen Sie Ressourcen erneut aus der Liste und prüfen Sie die Anzahl unter **Verweise**.
- Wenn Sie bei einer früheren Nachricht **Bearbeiten und senden** wählen, wird die ursprüngliche Frage in einen leeren Composer übernommen und ein vorhandener Entwurf nicht überschrieben. Eingefügte `@`- und `/`-Namen sind einfacher Text; die ursprünglichen Verweise und Anhänge werden nicht wiederhergestellt. Wählen Sie benötigte Agents, Skills und Anhänge erneut aus und prüfen Sie vor dem Senden die Anzahl unter **Verweise**. Wenn Sie erfahren, dass sich die Team-Berechtigungen geändert haben, wählen Sie sie zuerst erneut aus. Rückfragekarten der ursprünglichen Aufgabe müssen weiterhin auf der Karte beantwortet werden; ein erneutes Senden ist nicht nötig.
- Ist ein Skill in der `/`-Liste grau, lesen Sie den darunter angezeigten Grund. „Dieser Skill enthält noch keine schreibgeschützten Inhalte für Schnellverweise“ bedeutet, dass Sie ihn derzeit nicht im Composer auswählen können, auch wenn der Agent ihn normalerweise lesen kann. Die betreuende Person des Skills muss zuerst referenzierbare Inhalte hinzufügen.

Wenn Sie eine Formel Schritt für Schritt berechnet haben möchten, schreiben Sie das in die Frage. Stellt der ausgewählte Agent eine überprüfbare Umformung bereit, zeigt die Chatantwort die Formel und das gesetzte Ergebnis an. Breite Formeln lassen sich horizontal scrollen. Nicht überprüfbare Formeln werden nicht automatisch ausgefüllt.

## Wenn die Erstellung fehlschlägt

Bei einem Fehler behält die Karte Ihre Eingaben, sodass Sie sie bearbeiten oder es erneut versuchen können. Um Tools oder Arbeitsanweisungen nach der Erstellung zu ändern, öffnen Sie die Verwaltungsseite des Agents. Ob die Änderung die verwendete Version betrifft, hängt vom dort angezeigten aktuellen Status ab.
