# Find and manage files

Open **Library → Files**. Use **Assets** for uploaded files and delivered outputs, **Run data** for files saved during execution, and **Trash** for deleted files. Switch tabs if a file is missing from the current list. Search by name and narrow the list with the available filters.

Select the file name to open its preview and details. Use the available preview, download or knowledge-base actions. If the preview is unavailable, download the original where permitted. For a file revised in conversation, open the latest version and use **Version History** in Results to download a retained earlier version. [Find or download a file version](conversation-workbench.en-US.md#find-or-download-a-file-version)

You can select multiple rows for the bulk actions shown at the bottom. After deletion, use **Undo** or restore the file from **Trash**. Permanent deletion cannot be undone. If a knowledge-base or document reference blocks removal, inspect the file’s references before retrying. A file in the library becomes searchable as a knowledge source after you add it to the intended scope and indexing is ready. When knowledge bases are enabled, **Add to knowledge base** asks for a knowledge base instead, and that knowledge base decides who can search the file; **View in knowledge base** opens the knowledge base the file is in, with the file selected. The **Knowledge base** column also names that knowledge base when it is in My knowledge, the current Space or the Team. [Use the knowledge base](knowledge-base.en-US.md)

## Deliverables and storage management

When Files opens on **Deliverables**, select a file to read its content. Desktop selects the newest previewable delivery. On a phone, tap a filename to open it. Search by filename or use Filters to narrow results by Space, conversation, date or format. Use **Uploads**, **Run data** or **All files** for material without a recorded delivery. Details shows references and retained versions.

Open **Manage storage** for your usage, retention reasons and trash. A deleted file shows its recovery deadline. Use **Keep this version** to exempt a runtime file from automatic cleanup. Restoring an automatically removed file keeps it available until you release the exemption.

Team owners and administrators can open **Team settings → File retention and cleanup**, select 30 days, 90 days, Off or the deployment default, then preview the impact. Applying the reviewed change can include the eligible existing files shown in the preview. Figures describe recoverable files moved to trash. Storage is reclaimed after permanent removal.
