# 管理团队模型设置

在 **模型分工 → 知识库 → 检索返回数量** 中，默认每次返回 **15 条**。可选 5、10、15、20、30 或 50 条，修改数量不需重建索引。更多结果可能改善覆盖面，也会占用更多模型上下文；权限与相关性过滤可能使实际数量更少。已有 1–50 之间的自定义值仍可保留和选择。

团队负责人和管理员可在「团队设置 → 模型」管理团队使用的模型服务。页面有「模型连接」「模型分工」和「外部能力」三个标签。先在「模型连接」添加服务并维护模型，再到「模型分工」选择各项任务使用的模型；在「外部能力」配置图片生成和联网搜索。索引更新状态在知识库的「文件」视图查看。

## 1. 管理连接与模型能力

在「模型连接」标签中选择「添加连接」，或打开已有连接的编辑入口。填写服务地址、认证及所需参数，填写服务提供的模型 ID，并勾选需要使用的能力。若连接只用于图像生成或搜索，可以暂不填写模型目录，先保存地址和认证，再到「外部能力」配置服务模型。这个页面只维护当前连接，不设置模型用途。

模型目录中的每个模型都有「输入」「命中缓存的输入」「输出」三个额度系数，未填写时均为 1，已有模型也一样。只有服务返回缓存命中用量时，才按缓存输入系数计算那部分 token；其余输入按输入系数计算。系数范围为 0 至 1000，最多保留六位小数。保存后，每次新模型调用会记录当时生效的系数；此前调用保留原系数，即使同一项任务仍在继续。服务价格变化时，请同步检查这些系数。计算方式和用量明细见[查看和补充额度](credits.zh-CN.md)。

「上下文窗口（Token）」表示模型的总上下文容量，包括指令、对话、工具输入和回复所需空间。服务文档提供确切容量时可以填写；否则留空，继承页面注明的连接容量、模型目录值或系统默认值。页面显示的参考值不会自动保存为你的覆盖设置。修改这里不能扩大服务商实际支持的容量。

选择「制定验证计划」，查看要检查的能力、请求数量和费用提醒，确认后开始。确认、进度和结果都显示在当前页面；结果更新模型目录中对应能力的标签。验证会访问模型服务，可能消耗额度，但不会自动保存配置。

修改地址、认证、模型 ID 或能力相关参数后，旧验证结果可能不再适用，需要重新验证。连接保存后，返回模型设置总览，在生产分工中安排用途。尚未设置主模型时，保存连接不代表团队已经可以使用模型。

若模型或连接仍被使用，先到生产分工或外部能力页面更换正在使用的模型，再移除它。

自建或云平台托管的兼容 Chat Completions 服务，流式请求使用已保存的服务地址。任务需要确认用量时，服务须在流式响应中返回输入、输出 token 数；若未返回，请服务管理员开启支持或选择兼容模型，Bowra 无法凭缺失响应确认用量。能力验证只是小规模连接测试，修改服务后还应试一次有代表性的对话任务。

「模型输出容量（tokens）」描述模型单次最多可生成的内容。页面直接显示默认数值及来源：此模型、连接、目录，或未知能力的保守假设。普通请求自动解析额度，最多 256,000 tokens；未知能力使用 32,000，模型能力更小时优先采用较小值。实际调用还会为输入留出空间。这些数值是上限，不是预计消耗。自定义部署 ID 应按服务文档填写容量；「使用继承容量」移除模型级覆盖。只保存其他字段不会写入推断默认值。

页面中的「请求输出额度」显示自动、固定、封顶或不发送，不同能力有例外时分别显示。单次限额在下方「请求参数」中设置；模型容量与请求策略各有用途。不发送代表服务端上限未知；明确固定的限额保持原值，并须符合模型容量和上下文空间。

模型输出达到上限时，Bowra 会利用早先成功结果，最多两次要求模型改成更小但完整的操作；截断的工具批次不执行，早先成功写入不重做。对话运行状态会显示纠正过程。仍无法完成时保留先前成功结果，并提示缩短报告或检查输出设置；原有时间和步数限制继续生效。

## 自动压缩上下文

模型编辑器中的「自动整理上下文」默认开启。普通智能体对话需要更多空间时，Bowra 会摘要较早的内容，并保留近期原文。每个智能体按自己使用的模型设置执行。过程中，对话仅显示轻量的「正在整理上下文…」状态，不需要关闭弹窗，可以继续阅读。

没有特别需求时，高级 token 参数保持「自动」。触发值决定何时开始整理，近期原文值表达希望保留多少原始内容。Bowra 会根据模型容量和必需输入调整实际目标；调高数值不能突破服务商容量。清空数字恢复自动计算，使用重置操作可恢复全部压缩默认值。

关闭自动压缩会保留已设置的数字，以及此前已经生成的摘要。请求容量不足时，Bowra 会让本次请求不携带较早且已完成的上下文，不生成摘要。开启自动压缩但摘要不可用时，也可通过同一方式继续。已保存的会话记录不变，但模型可能不再记得这些较早的细节。当前问题和最新工具结果仍会保留。如果仅必需输入就已超过容量，可以手动整理上下文、选择容量更大的合适模型，或缩短问题、减少材料，再在原会话重发。摘要会调用模型，计入原任务的时间和用量限制。专用文档生成及其他独立恢复流程仍遵循各自规则。

会话空闲时，可通过 **⋯ → 整理上下文**手动整理，不改变自动压缩开关。见[会话操作](conversation-workbench-actions.zh-CN.md#整理较长的会话)。

## 配置请求参数

展开 Chat、Tool 或 Vision 模型行的「请求参数」，根据精确模型版本与 API 的官方文档选择参数档案。档案只说明怎样发送，不证明服务商支持；未确认推理协议时保留未知。

在「模型默认值」编辑共用配置，仅有例外时使用「能力覆盖」，例如 Tool 思考开启、Chat 与 Vision 关闭。只有编辑的字段成为例外。选择继承移除例外；「不发送」则移除请求字段，两者不同。始终思考档案没有关闭选项；思考预算须给输出留余量，不兼容的采样配置需先修正。

生成控制包括 temperature、top_p 和输出限制；并行工具是开启／关闭选择，不是数字。连接支持时，「高级参数」可填写精确字段名与 JSON 值，请勿放入提示、凭据、请求头或运行时控制。非法 JSON 会留在草稿中，修正后才能保存。旧能力 JSON 保持原范围，「检查转换」展示支持的转换，确认后才修改草稿。

选择能力并点「刷新预览」，查看安全的合成请求投影与参数来源。预览不访问模型服务，也不保存；未知高级值会隐藏且保持未验证。编辑后旧预览会标为过期。测试服务商接受情况仍用原有「制定验证计划」，确认请求数量和可能费用后开始。过大的固定预算不会被偷偷降低；无法探测时会说明安全上限和处理方法。

保存连接后重新打开确认。若出现审阅弹窗，先处理校验问题或确认风险，再应用修改。预览或验证本身不会使草稿生效。

## 2. 设置生产分工并查看依据

评估模型也用于智能体评测、要点校准和 Coach 检查；默认是「自动」，即选一个与主模型不同的模型：优先选其他服务商的对话模型，没有时选同一连接里的另一个对话模型；「进阶」折叠行会写明自动选了哪个模型。如果主模型是团队唯一的对话模型，页面会直接说明评估只能用主模型，这时请在模型连接里再加一个对话模型。智能体评测不会另外要求填写模型或地址。

选择「编辑分工」，分别设置主模型、备用模型、轻量模型与评估模型，以及知识库向量、重排、文档识图和行抽取模型。只能选择已保存连接中的模型。

分工引用连接中精确的模型 ID。替换连接中唯一的对话模型时，草稿会把相关分工一并指向新 ID；应用前请检查这些修改。如果连接有多个对话模型，请先明确调整受影响的分工，再移除旧 ID。模型 ID 必须是服务方实际接受的值；只在 Bowra 中改名不会改变服务方的模型目录。

验证当前分工只检查所选用途需要的能力；可以逐项验证，也可以选择一批能力。在同一个弹窗中选择验证项、确认请求数量、查看进度及结果；确认前可返回调整选择。

页面分别显示已有验证结果和最近一次验证的情况。网络错误或取消验证不会清除仍有效的成功结果。

在「模型分工」标签的「生产分工与验证依据」中可以查看每项模型用途的验证记录。页面先显示最需要关注的几项；记录较多时，点「显示其余 N 项验证记录」查看全部，点「收起验证记录」回到简短列表。每项记录显示用途、模型、计划使用的能力、已有验证依据和最近一次尝试。需要重新验证某一项时，点该项的「验证」，再点「开始验证」确认；也可以用「验证当前分工」选择多项一起验证。验证会向模型服务发起请求。验证结果供排查使用，不能单凭一次网络错误判断配置不可用。修改分工后检查并保存；如果更换向量模型需要重建索引，保存前会提示影响并要求确认。索引完整发布前继续使用原索引。

## 失败自动重试次数

「模型分工」标签下的「模型行为」只有一项设置：「失败自动重试次数」。模型调用在模型还没开始回复时就失败（例如响应超时、连接失败或服务暂时出错），Bowra 会自动重新调用，最多重试这里设置的次数。默认 3 次，可设 0–5 次；设为 0 表示不重试。修改后点输入框旁的「保存」；这项设置单独保存，不会改动模型分工。

只有在模型尚未开始回复时才会重试，因此不会出现同一段回答发两遍。每次重试都计入本轮的时间上限；剩余时间不够时会停止重试并报告失败。重试进行中，对话的运行状态会显示类似「模型响应超时，正在重试（1/3）」的提示。如果页面提示模型配置已被修改，请刷新页面后重新设置。

## 3. 管理外部能力

选择「外部能力」标签会打开独立页面，查看图片生成和联网搜索的状态。图片和搜索配置页的返回按钮会回到外部能力总览。

在图片生成或联网搜索所在行选择「配置」或「修改配置」，进入对应页面。选择已有连接，填写服务模型及调用方式，再选择团队启用的模型。地址与密钥仍在连接管理中维护。

「已配置」表示已填写服务设置，还需要确认服务能正常使用。图像生成和联网搜索分别设置，不会改变其他任务使用的模型。

知识库索引更新状态与失败重试入口位于「知识库 → 文件」。若要更换知识库模型，请进入「模型分工」编辑分工。

## 保存与离开页面

各部分分别编辑和保存。连接表单点击「保存」后会校验并写入，成功后返回模型设置列表；若需要确认风险或处理校验问题，会直接打开审阅弹窗，处理后在弹窗中应用。其他部分使用检查后应用流程。取消或放弃草稿不会修改已保存配置，离开有未保存修改的页面时会提示。

## 对话中的模型选择

在对话中选择模型时，这个偏好会用于主要分析任务；其他任务继续按团队的生产分工选择模型。团队尚未完成模型配置时，请先由负责人或管理员配置，不会自动借用其他团队或平台的模型。

## 使用 Bowra 服务

管理员启用服务后，「添加连接」旁会显示「使用 Bowra 服务」，团队尚未配置任何连接时也可使用。只有团队负责人和管理员可以操作。请通过使用 443 端口的 HTTPS 网站域名打开本应用；Bowra 无法回调 HTTP、localhost 或 IP 地址。

点击「使用 Bowra 服务」，在 Bowra 登录并同意授权。返回后，模型服务地址、密钥和模型名称会导入为 OpenAI 兼容格式的草稿，此时尚未生效。请检查连接及预期使用的 Chat／Tool 能力；模型名称本身不代表已验证这些能力，可按需执行现有验证操作。团队没有主模型时，单模型会预选为主模型，多个模型则需选择主模型。已有主模型分配保持不变。点击「检查并应用」，完成所需确认后生效。

新导入的 Bowra 连接会自动在服务地址末尾补上缺少的 `/v1`，保留已有路径，且不会重复添加 `/v1`。已保存的连接不会自动修改。若已有 Bowra 连接缺少 `/v1`，请编辑服务地址，在末尾补上 `/v1`，再检查并应用。

Bowra 没有可用模型时不会导入连接；取消授权不会改变现有设置。每次同意授权都会在 Bowra 创建新密钥，即使兑换失败或放弃草稿也不会自动撤销。结果不确定或放弃导入草稿时，请在 Bowra「API Keys」按应用名称和创建时间找到本次密钥，必要时只禁用或删除该密钥，再重新连接。不要为了刷新模型列表反复授权。在本应用删除连接只删除本地凭据副本，不会撤销 Bowra 密钥。
