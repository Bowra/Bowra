# 权限参考：角色与操作

本页用于快速确定某项操作的负责人。团队、空间、资源、平台能力和数据权限分别检查。

## 记住四条规则

1. 团队角色决定团队管理职责，不自动授予空间成员资格或业务数据访问权。
2. 空间角色控制空间内协作，不代表拥有每个 Agent 或 Skill 的内容。
3. Agent 的使用范围与发布状态决定谁能发现和使用它；编辑由作者或明确指定的管理者负责。
4. 数据查询使用当前成员本人的数据身份。分享报告或 Agent 不会转交该身份。

## 谁管理什么？

| 对象或操作                  | 主要负责人                         | 说明                                             |
| --------------------------- | ---------------------------------- | ------------------------------------------------ |
| 团队成员、服务与审批        | 团队负责人或管理员                 | 不会转交其他成员的私人数据身份                   |
| 空间成员及设置              | 空间管理员                         | 团队管理员不会自动加入每个空间                   |
| 成员创建的 Agent 内容与版本 | Agent 作者                         | 作者选择使用范围并发布；可能需要审批             |
| 内置 Agent 启停和配置       | 团队负责人或管理员                 | 产品定义的工具和输出格式不能任意替换             |
| 个人 Skill 编辑和个人启停   | Skill 作者或当前成员               | 个人开关只改变该成员的使用                       |
| 团队 Skill 审批和整体状态   | 团队负责人或管理员                 | 成员不能覆盖团队停用状态                         |
| Outcome 定义                | 产品或部署维护者                   | 团队角色配置已支持功能，不能创建未支持的结果契约 |
| 团队能力                    | 团队负责人或管理员                 | 成员可以为本人拥有的 Agent 选择工具与 Skill 组合 |
| 外部业务数据                | 数据系统管理员及成员本人的数据身份 | 分别检查数据源和个人授权                         |

## Agent、能力、Outcome 与 Skill

**Agent** 封装工作角色及其依赖。**团队能力**由管理员维护，将可复用工具与 Skill 组合起来。**Outcome** 描述 Agent 承诺的成果，可能展示证据和可用性；它们都不会额外授予权限。**Skill** 是可复用方法。保存草稿、发布版本、审批团队发布以及为个人启用方法，是不同负责人控制的不同操作。

操作被拒绝时，先确定具体资源和动作，再依次检查团队、空间、资源、能力和数据边界。排查步骤见[排查访问问题](permissions/troubleshoot-access.zh-CN.md)。
