# Agent veröffentlichen

Nutzen Sie diese Anleitung, wenn Sie einen Agent erstellt haben und Kolleginnen und Kollegen ihn verwenden sollen. Eine Arbeitskopie zu speichern, eine Zielgruppe festzulegen, eine Freigabeprüfung zu bestehen und eine Version zu veröffentlichen sind getrennte Schritte.

## Bevor Sie beginnen

Prüfen Sie, ob Sie den bearbeiteten Agent besitzen, seine Anweisungen und Abhängigkeiten fertig sind und die benötigten Skills, Modelle, Tools und Datenzugriffe für die Zielgruppe verfügbar sind. Behaupten Sie nicht, ein Agent könne auf Daten zugreifen, nur weil Sie selbst dazu berechtigt sind.

## Zielgruppe festlegen und veröffentlichen

1. Öffnen Sie beim Agent **Von mir erstellt → Konfiguration verwalten**.
2. Wählen Sie die vorgesehene Zielgruppe und speichern Sie die Freigabeeinstellungen.
3. Verwenden Sie die von der Seite angebotene Veröffentlichungsaktion. Manche Abläufe zeigen **Sicherheitsprüfungen ausführen**, andere **Kandidatenversion vorbereiten**.
4. Prüfen Sie Warnungen, beheben Sie erforderliche Probleme und reichen Sie die Version ein.
5. Ist eine Freigabe erforderlich, prüft eine teamverantwortliche oder administrierende Person die Kandidatenversion im Teamablauf und genehmigt oder lehnt sie ab.

Nach **Kandidatenversion vorbereiten** bezieht sich die Veröffentlichungsprüfung der Testressourcen auf diese vorbereitete Version. Fehlende Tests oder ein Infrastrukturfehler bedeuten, dass die Nachweise noch nicht vollständig sind. Beheben Sie das Problem und starten Sie die Prüfung erneut. Nachdem die Kandidatenversion zurückgezogen wurde, beziehen sich Standardtests wieder auf die aktuelle Live-Version; frühere Testprotokolle bleiben verfügbar.

## Prüfen, ob Kolleginnen und Kollegen den Agent verwenden können

Die Kollegin oder der Kollege sollte den veröffentlichten Agent mit einem Konto in einem Bereich finden, der zur Zielgruppe gehört, ihn übernehmen und eine zulässige Aufgabe ausführen können. Prüfen Sie Verfügbarkeit und Ergebnis. Übernahme oder Freigabe setzt weder Teammitgliedschaft, Bereichszugriff, verfügbare Abhängigkeiten noch die Datenidentität der Person außer Kraft.

## Aktualisieren oder zurückziehen

Speichern und veröffentlichen Sie eine neue Version, wenn sich das Verhalten ändert. Bestehende Nutzerinnen und Nutzer können die bisherige veröffentlichte Version weiterverwenden, bis die neue Version genehmigt und verfügbar ist. Heben Sie die Freigabe auf oder deaktivieren Sie den Agent, wenn er nicht mehr verwendet werden soll. Prüfen Sie vorher abhängige Skills und Abläufe.

Nach der Bearbeitung eines Skills, den der Agent nutzt, ist keine neue Veröffentlichung nötig. Ab dem nächsten Aufruf verwendet der veröffentlichte Agent die zuletzt genehmigte Version eines Team-Skills bzw. die aktuelle Version Ihres persönlichen Skills.
