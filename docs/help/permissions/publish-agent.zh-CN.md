# 让同事使用你创建的 Agent

你可以将自己创建的 Agent 开放给指定同事、群组或全团队。本文从已有 Agent 开始，说明如何选择受众、发布，以及由管理员完成审批。

## 开始之前

- 你拥有这个 Agent，且能从 Agent 管理页的 **我创建的** 进入 **管理配置**。
- Agent 未归档，所需工具和 Skill 当前可用。
- 需要分享给他人时，先确认依赖也适用于目标受众。个人 Skill 仅能用于私用 Agent。

个人 MCP 工具可以在分享时保留绑定，但只在作者本人运行时可用；同事运行时不会装配这些工具。请确认 Agent 不依赖这些工具也能完成向同事承诺的工作。

“拥有者”指这个 Agent 的作者/当前归属者。团队管理员身份不能代替其他作者编辑 Agent。

没有自定义用例不会阻止发布，也不需要填写接受理由。页面及共享智能体的审批详情会说明回答质量尚未评测。其他安全检查、实际测试失败和共享智能体审批仍按原规则处理。

## 选择分享范围

| 选择           | 适用情况                 | 发布时会发生什么                                 |
| -------------- | ------------------------ | ------------------------------------------------ |
| 仅自己         | 还在准备，或只供自己使用 | 随时可以发布私用版本；测试结果只作参考           |
| 指定成员或群组 | 只给某些同事使用         | 根据风险和当前评测要求，直接发布或进入管理员审批 |
| 全团队         | 面向整个团队提供稳定功能 | 提交管理员审批                                   |

新受众在版本生效后才获得相应使用资格；作者的数据权限不会随 Agent 一起转给同事。

## 保存分享设置

1. 打开 Agent 市场，进入其管理页面，选择 **我创建的**。
2. 找到要分享的 Agent，选择 **管理配置**。
3. 在 **谁可以发现和聘用** 中选择分享范围。选“指定成员或群组”时，通过 **查找成员或群组** 搜索并勾选对象。如果智能体绑定了个人工具，这里会提示同事无法使用这些工具；请确认同事有权限使用的其他工具足以完成任务。
4. 检查页面是否提示依赖不可用、个人 Skill 仅限私用，或尚未选择有效受众。选择有依赖的 Skill 时，页面会自动补齐可用的必需 Skill；依赖不存在时不能保存，请先联系管理员安装或开放该 Skill。
5. 选择 **保存草稿**，确认出现保存成功提示。
6. 在 **这次更新说明** 中说明这次开放了什么或修改了什么，然后按下方与你页面相符的流程发布。

保存成功时，大家用的仍是已发布版本；还需要完成发布。

## 发布方式一：页面显示“运行安全检查”

1. 选择 **运行安全检查**，等待结果。
2. 若结果要求处理问题，修正草稿、保存，再重新检查。不能仅凭填写更新说明跳过检查。
3. 检查允许继续后，选择页面提供的 **启用新版本**（仅自己使用的 Agent 为 **应用新版本**） 或 **提交管理员审批**。
4. 查看返回结果：显示“新版本已成为当前可用版本；这不代表已上架市场。”代表已生效；显示“已提交团队审批”代表仍需等待管理员。

## 发布方式二：页面显示“测试这次修改”

版本评测默认开启，管理员可以明确关闭。开始前选择一个你有权访问、用于本次验证的空间；私用发布由你决定，面向其他成员发布需要团队审核。

1. 保存草稿后，在“评测”或“发布”页选择 **测试这次修改**，等待结果。它会用最新保存的草稿和已发布版本跑同一批用例。
2. 出现变差的用例或“没能运行”时，按页面写明的原因处理后选择 **重新测试**；环境故障请联系相应维护者。
3. 如果存在需要作者确认的提示性风险，先读清影响并处理。仅在你能承担该影响时记录决定。
4. 私用智能体随时可以选择 **发布为 v2**：测试只作参考，没通过、没有结论或还没测试也能发布，对话框会用一句话说明测试情况，可以填写发布说明；共享智能体在测试通过后选择 **提交审批（发布为 v2）**，同样可以填写发布说明，审批人和版本历史里都能看到。
5. 检查结果是等待审批还是已发布。测试本身不会替换当前生效版。

如果必需用例在已发布版本和这次修改中都未通过，测试结果会指出评测组、用例和这次修改的通过次数。选择「查看用例」比较回答，再检查该用例的评测要求并修改草稿，然后重新测试；两个版本都失败的用例仍会阻止共享智能体的发布，私用智能体可以照常发布。

测试完成后，“评测”页显示同一个测试结果。尚未完成所需评测，或评测因环境故障未能完成时，不代表证据已就绪；请处理原因后重新测试。

## 管理员怎样审批？

以下操作由团队负责人或团队管理员完成：

1. 打开 Agent 管理页面，选择 **团队治理**。
2. 在 **待审批的 Agent 版本** 中找到本次申请，选择 **开始审批**。
3. 核对拟发布的介绍、本次更新、使用范围和检查结果，确认它们符合预期用途。右侧集中显示风险和审批操作；需要更多配置细节时，展开 **查看运行配置详情**。
4. 同意时选择 **批准并发布**；不同意时选择 **不批准此次发布…**，在弹窗中选择主要原因，再选择 **确认不批准**。选择 **返回继续审核** 可取消，不会提交决定。
5. 确认页面显示“候选已批准并发布”或“候选已拒绝”。若提示候选已变化或证据不足，重新查看最新状态后处理。

评测卡片显示“Owner 没有提供用例”时，表示只跑了基础安全检查：它能说明智能体不越界，不能说明回答质量。需要更多证据时，可以选择拒绝原因「安全或效果证据不足」。

审核内容是本次已提交的版本。管理员无法在此编辑作者未提交的草稿，也不会获得作者私有提示词或测试数据的完整内容。

## 怎样确认同事已经能用？

1. 作者确认新版本已发布，而非仍处于“审批中”。
2. 请一位目标受众中的同事按 [聘用 Agent](use-agent.zh-CN.md) 检查是否能发现和聘用它。
3. 由同事在获准空间提出一个符合该 Agent 用途的任务，并检查实际执行情况。

能发现和聘用说明分享关系可用；任务能否完成还取决于该同事的空间、依赖及数据权限。

## 后续修改、撤回或发布失败

- **改行为或受众：** 回到 **管理配置**，修改草稿并重新发布。保存后不会立即改变同事正在使用的版本。
- **只改了 Agent 用到的 Skill：** 不需要重新发布。团队 Skill 审批通过后、个人 Skill 保存后，已发布的 Agent 下一次调用就会用新内容。
- **已有待审版本：** 先打开本次候选查看状态；需要取消时使用页面提供的撤回操作，再按当前工作台提示准备新的发布。
- **只能看到“聘用”，没有“管理配置”：** 你拥有使用资格，但不是这个 Agent 的作者；请联系作者修改。
- **个人 Skill 阻止分享：** 改为使用适合目标受众的团队/内置 Skill，或将 Agent 保持为“仅自己”。
- **管理员不能批准：** 请作者处理该候选的验证或评测问题；管理员的审批不能替代这些条件。
