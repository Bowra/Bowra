# 将 Skill 发布到团队并提交更新

你可以把自己的技能（Skill）提交到团队，让获准成员复用方法和工作流。后续更新会先进入审批，团队在此期间继续使用旧已批版本。

## 个人使用与智能体配置有什么区别？

在 **技能与流程 → 我的技能** 管理个人版本。启用且没有待处理导入问题后，普通对话可由内置执行智能体按任务需要读取，你也可以在提问时明确指定技能名称。保存或启用不代表每个任务都会采用；读取说明也不会开启脚本执行权限。

自建智能体需要单独配置：直接选择技能、通过所选插件包含，或配置为允许用户在单个任务中选择的只读方法。个人技能要求智能体的使用范围为 **仅自己**。若需配置给与同事共享的智能体，请按下方步骤提交到团队。团队版本审批通过、启用且对全团队可用后，再到智能体配置中选择该团队版本，保存并完成应用或发布流程。审批通过不会自动添加到智能体。

## 开始之前

- 已有可编辑的个人 Skill；系统内置 Skill 在用户侧只读。
- 团队已开放 Skill 提交功能，并具备所需外部工具功能许可。
- 更新已有团队 Skill 时，你是其原作者。复制他人的 Skill 可用于个人改良，但不能覆盖对方的同名团队 Skill。

本文先写普通作者的提交流程。团队负责人/管理员直接发布或维护内容的差异见文末。

## 第一次提交

1. 打开 **技能** 页面，在 **我的技能** 中选择要提交的 Skill。
2. 在详情的 **说明** 中阅读正文。需要修改时选择 **编辑**，完成后选择 **保存**；检查“已保存”提示。
3. 检查方法说明、附属文件和使用的工具是否适合团队共享。需要实际运行的脚本，还应确认当前部署支持执行。
4. 在详情的 **团队状态** 区域选择 **提交到团队**。
5. 确认状态变为“审批中”，由团队负责人或管理员按下方步骤审批。

第一次提交处于审批中时，其他成员尚不能把它作为已发布团队 Skill 使用。

## 更新自己已经发布的 Skill

1. 在 **我的技能** 中打开对应个人版本。若个人版本不在库中，可先从 **团队技能** 打开自己发布的 Skill，选择 **复制为我的技能**。
2. 若提示已有同名个人技能，先确认是否需要保留个人修改；只有确定可以替换时才选择 **覆盖**。
3. 在个人版本中完成编辑并 **保存**。需要改附属文件时，进入 **文件**，打开目标文件，编辑后保存。
4. 当 **团队状态** 显示“团队版落后”时，选择 **提交更新**。
5. 确认状态变为“更新审批中”。旧的已批团队版本继续可用，当前个人修改尚未替换它。

若个人版本与团队已批版一致，会显示“已同步到团队”，无需重复提交。若已有更新在审，先等待或使用 **撤回**，再按当前状态处理。

更新通过审批后，使用该 Skill 的智能体会在下次运行时改用新版本；智能体所有者会看到“所用技能已更新”，并被建议重新测评。如果团队版本本身被直接编辑并重新进入审批，在负责人或管理员重新审批前，包含它的智能体不能使用它，也不能带着它保存或发布。

## 管理员审批 Skill

团队负责人或团队管理员按以下路径操作：

1. 打开 **团队设置 → 我的流程**。该入口打开的页面标题为 **团队流程**。
2. 在 **待审批** 区域找到目标 Skill，核对名称、作者和提交时间，区分首次提交与更新。
3. 选择 **展开预览**，阅读本次待审内容和风险提示。
4. 同意时选择 **通过**。需要修改时选择 **拒绝**，填写理由，再选择 **确认拒绝**。
5. 刷新后确认这次申请已不在待审批列表；请作者在个人 Skill 的团队状态中确认结果。

如果提示“内容已更新，请重新查看后再操作”，重新打开预览，核对最新内容后再作决定。

## 怎样确认已经对团队生效？

作者在个人版本中确认 **团队状态** 显示“已同步到团队”。再请一位获准成员打开 **技能 → 团队技能**，确认能找到对应 Skill，并检查其启用状态。

审批通过与启用是两回事。若显示“管理员已停用”，请团队治理者在 **团队流程** 检查全局状态；成员自己在技能页打开的开关只影响本人。

单独能读 Skill 不代表有权运行其中的脚本；把带脚本的 Skill 添加到智能体后，该智能体可以在沙箱中运行这些脚本（见[创建智能体](../create-agent.zh-CN.md#了解智能体可以使用哪些技能)）。准备输入期间，如果 Skill 被停用、执行权限被撤销或导入变为待处理，脚本会在启动前停止。先解决可用性或权限问题再重试；停用 Skill 不能代替取消已经运行的脚本。

## 被拒绝或需要取消时

- 显示“已被拒绝”或“更新被拒绝”：阅读 **理由**，修改并保存个人内容，选择 **重新提交**。
- 需要取消待审内容：在个人 Skill 的团队状态区选择 **撤回**，刷新后确认已退出待审状态。撤回待审更新不会把旧已批版替换为新内容。
- 提示“团队已有他人创建的同名技能”：请联系原作者协作；个人副本不提供覆盖他人团队 Skill 的权限。

## 管理员直接编辑的影响

团队负责人/管理员提交全团队 Skill 可直接形成已批准内容，状态不一定经过“审批中”。

管理员在可见且有管理权的团队 Skill 上直接编辑正文或文件时，**保存会立即更新团队正在使用的版本，并清除旧试跑结论**。执行前请确认内容已经适合共享；这一行为与 Agent 的“保存工作副本后另行发布”不同。

## 没有“提交到团队”按钮？

先确认打开的是 **我的技能** 中的个人版本，并已退出编辑、完成保存。系统内置 Skill、团队版本详情、未开放团队提交功能，以及不同的团队同步状态，会显示不同操作。仍不符合预期时，请团队管理员检查功能开放情况。

## 查看使用位置

在技能详情中查看使用位置，可以了解哪些你有权查看的智能体正在依赖该技能。列表只展示你有权访问的内容；查看使用位置不会授予修改、停用或删除权限。

保存正文或管理文件时，编辑器会检查整包是否仍是打开时的版本。如果另一个窗口或 Coach 已保存，本地文本会保留在编辑器中。如果保存提示 Skill 已变化，请先复制需要保留的文本，重新打开当前文件并比较后，再提交修改。冲突回执不能说明哪个版本当前有效；完成比较前保留尚未保存的文本。

内容保存成功与导入检查完成是两个结果。检查失败或过期时，已有待处理状态会保留；请对当前文件重新检查，失败本身不能证明此前的阻断项已解决。

Coach 技能创作可用时，可以在对话中要求创建或编辑本人的个人技能，说明要修改的文件或行为。其他包文件和启用偏好会保留。保存成功会直接改变个人版本；导入检查和业务试用是另外的结果。如果保存中断，先在原对话中恢复原操作，再继续修改。发生冲突时先比较当前文件。提交团队和审核仍按原流程办理。

对话提示技能已保存时，也请阅读检查提示。缺少触发示例等黄色提示可能需要完善；有阻断项或检查未完成时，应先处理再依赖该技能。已保存、已启用不代表自动选择或业务效果已经验证。若技能在本次保存后又有变化，请先检查当前版本再继续。明确只要草稿时，不会修改已保存的技能。
