# 排查功能或数据无法访问

当你找不到入口、无法使用已聘用的 Agent，或数据查询被拒绝时，先从看到的现象定位问题，再联系对应的人。

## 先确认这三件事

1. 当前登录账号、团队和空间是否正确。
2. 失败的是哪一步：找不到资源、无法编辑、无法发布，还是任务运行失败。
3. 页面显示的原始提示是什么。记录资源名称和发生时间；向维护者反馈时不需要发送密码、密钥或完整业务数据。

## 能看到 Agent，但无法使用

1. 在 Agent 管理页面打开 **我聘用的**，查找目标 Agent。
2. 若显示 **我已停用**，选择 **启用**，刷新后确认状态。
3. 若显示 **访问已撤销**，联系作者确认分享范围，同时让管理员检查当前团队和空间成员资格。
4. 若显示 **已聘用，暂不可用**，打开详情查看可用性提示。由作者检查 Agent 发布状态及依赖；团队连接问题交给团队管理员处理。
5. 处理后在获准空间重试同一类任务，确认不再出现原访问错误。

已经聘用不代表永久保留执行资格；分享范围、成员资格、依赖或发布状态变化后，需要按当前条件重新判断。

## Agent 能运行，但不能查询北极九章数据

### 第一步：确认团队连接

请团队负责人或管理员打开 **团队设置 → 数据源**，确认当前团队有启用的北极九章连接。没有连接或连接失败时，由该管理员完成配置或修复。

### 第二步：确认你的数据身份

请负责北极九章接入的人检查当前 Bowra 用户是否关联了有效的数据身份。不要使用其他同事的账号来证明你已有权限。

### 第三步：确认可查询的数据范围

如果对话要求选择北极九章工作区，从向你提供的可访问列表中选择目标。列表没有目标工作区时，请北极九章侧的数据权限维护者检查你对应身份的访问范围。

“销售空间”与“北极九章销售工作区”是两个对象：能进入前者不代表能查询后者。

### 第四步：重试并核对

在正确空间重新提出原查询，确认原授权错误已消失，并核对结果使用的数据范围。查询成功但内容为空，也可能是筛选条件、时间范围或数据本身的问题，需要继续检查业务口径。

北极九章访问失败不影响另行获授权的 Power BI 查询、上传文件分析或计算。请在问题中说明希望使用的数据源。只查询 Power BI 的任务无需选择北极九章工作区；分析文件时使用你上传的数据，不会悄悄换成数据库查询结果。

## 无法编辑或发布

| 现象                         | 先检查什么                                   | 谁处理                                          |
| ---------------------------- | -------------------------------------------- | ----------------------------------------------- |
| 能使用 Agent，没有“管理配置” | 是否在“我创建的”，你是否是该 Agent 拥有者    | Agent 作者                                      |
| Agent 保存了，同事看不到变化 | 是否只保存工作副本，或发布还在审批中         | 作者完成发布；需要审批时由团队负责人/管理员处理 |
| Skill 没有“提交到团队”       | 是否打开个人版本、完成保存，以及当前团队状态 | 本人先检查；功能未开放时联系管理员              |
| Skill 显示“更新审批中”       | 更新是否尚未批准；同事仍使用旧版是正常情况   | 团队负责人/管理员到“团队流程”审批               |
| 同名团队 Skill 不能被覆盖    | 该团队 Skill 是否由他人创建                  | 联系原作者协作                                  |
| 团队配置无法保存             | 当前身份是否有管理权、服务是否可用           | 团队负责人或部署维护者                          |

## 能看报告，却不能查看附件或重新取数

请分别检查报告、附件与原始数据的授权。别人分享的报告可以包含其已生成的内容，但不会因此把作者的私有会话、所有附件或数据身份一起交给你。

需要附件时联系文件/报告拥有者检查分享；需要重新查询时联系数据权限维护者检查本人的数据范围。

## 管理员设置了限制，但仍能调用

请团队治理者确认限制作用于哪个资源和操作，并让部署维护者确认通用细粒度规则是否处于强制执行模式。部分部署采用观察模式，只记录部分拒绝判断。

修正后应由被限制的目标身份验证对应操作。其他机制，如团队/空间身份检查、Agent 受众及内容分享读取，仍有各自的检查；不能因为通用规则处于观察模式就认为所有访问限制都失效。
