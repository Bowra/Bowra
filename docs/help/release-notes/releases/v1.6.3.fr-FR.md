# v1.6.3

Les connexions distinguent la capacité de sortie des limites de requête. Les requêtes ordinaires réservent de la place à l’entrée et respectent les limites configurées. Après une sortie tronquée, la tâche peut demander jusqu’à deux actions complètes plus petites en conservant les résultats déjà obtenus. Les lots d’outils incomplets ne sont pas exécutés. Une réécriture IA tronquée conserve le texte original.

Après actualisation ou réouverture, les cartes d’échec conservent le statut HTTP disponible, l’explication filtrée du service et l’action conseillée. Un résultat d’appel non confirmé arrête les nouvelles tentatives automatiques ; demander à un administrateur de le vérifier avant de renvoyer. Un rejet Responses nécessite de vérifier l’API choisie et sa configuration. Un HTTP 400 seul ne prouve pas une incompatibilité.

Choisir **Réviser dans le chat** sur un brouillon de document non publié disponible permet de sélectionner cette version précise et de conserver ses modifications antérieures. Vérifier le nouvel aperçu avant publication. Les contrôles des présentations respectent le débordement de texte pris en charge. Une question non enregistrée est signalée comme non créée ; les précisions peuvent être ajoutées dans le chat. Les réponses courtes complètes peuvent être évaluées. Relancer une ancienne évaluation pour obtenir un nouveau jugement.
