# 添加团队 MCP 工具

团队负责人或管理员可以在「能力中心 → 工具 → 管理工具源」中添加 MCP 工具，让团队中的智能体使用已选定的外部服务能力。添加的是一个 MCP 服务及其中选定的工具；它不会自动授予团队成员该外部服务的账号权限。

如果每位成员应在服务方使用自己的账号而不是共用账号，成员可以在「我的连接」中登录该服务，参见[连接个人 MCP 服务](personal-mcp.zh-CN.md)。

## 添加 MCP 服务并选择工具

1. 打开「能力中心 → 工具 → 管理工具源」，在「外部工具源」标签页点击「添加 MCP 工具」。
2. 选择「MCP 服务器」，填写服务地址；如服务要求认证，按提示填写凭据或完成授权。
3. 等待系统读取该服务提供的工具，勾选需要提供给团队智能体的工具。
4. 填写来源名称并确认添加。添加后可在工具列表中查看、验证、停用或编辑该来源。

凭据保存后不能读取或回显。请只连接可信服务，并使用权限最小的凭据。云端部署仅支持公网 HTTPS 地址；企业内网部署可以使用内网地址。
如果服务使用 OAuth，请用可向团队共享其可访问内容的账号登录。有使用权限的成员将通过智能体使用该账号的权限。授权后，在工具源上点击 **选择工具**，保存选择，再启用来源。工具较多时可按类别筛选，批量选择或清除当前结果。如果服务拒绝回跳地址，请通过已验证的 HTTPS 公开入口打开 Bowhead，再重新授权。

## 管理已添加的工具

每个来源都可以单独验证连通性、编辑名称或凭据，以及停用。停用后，新的调用不会再发往该服务；已开始的外部调用可能仍会完成。删除会同时清除该来源保存的凭据，且不可撤销。

## 刷新工具列表

MCP 服务新增或下线工具后，可以在该来源的操作中选择「刷新工具列表」（在卡片右侧的「⋯」菜单中）。系统会先读取服务当前提供的工具，并列出与已保存列表的差异：

- **新增工具**：服务新提供的工具。如果添加来源时只选择了部分工具，新增工具不会自动导入。
- **服务器已移除的工具**：服务不再提供、且未被导入的工具，移除不影响智能体。
- **将失效的已导入工具**：已导入但服务不再提供的工具。更新后智能体无法再调用它们，界面会同时列出受影响的智能体、运行中任务和定时任务；相关定时任务会暂停，确认依赖后才能恢复。如果该来源导入的工具全部被移除，更新后会自动停用该来源。
- **有变化的工具**：服务仍在提供、但说明或参数有变化的工具。每个工具会标明变化的内容以及是否已导入。更新后，智能体下次调用已导入的工具时即按新版本使用。

核对无误后点击「更新工具列表」才会生效；点击「取消」不会做任何更改。如果在你核对期间工具列表或其使用情况发生了变化，系统会重新读取并请你再次核对。没有任何新增、移除或变化时，界面会提示工具列表已是最新。

需要授权的 MCP 服务完成首次授权后才能刷新工具列表。

## 授权失效时

已授权的服务无需你操作即可持续使用：Bowhead 会在需要时自动续期；即使多个对话同时使用该服务，也只续期一次。如果服务不再接受该授权（例如长时间未使用而过期、有人在服务中移除了 Bowhead 的访问权限，或服务更换了登录服务器），工具源卡片会显示「待授权」和「授权」按钮。此时对话中的调用不会发出，智能体会提示用户联系团队管理员。

点击「授权」并重新登录该服务即可，已导入的工具保持不变。等待授权期间仍可停用该工具源；重新授权后即可再次刷新工具列表。

## 选择要导入的工具

如果要导入添加来源时没有勾选的工具，或刷新后新增的工具，可以在该来源的操作中选择「选择工具」（在卡片右侧的「⋯」菜单中）。如果来源只导入了部分工具，刷新新增工具后的提示中也会直接提供「选择工具」，新增工具会标为「新增」。

列表显示最近一次保存的全部工具，已导入的工具默认勾选。勾选需要提供给智能体的工具后点击「保存」。至少需要保留一个工具；如需停用全部工具，请关闭该来源。

如果取消勾选了当前已导入的工具，系统会先显示影响范围：将移除的工具，以及使用该来源的智能体、运行中任务和定时任务。点击「确认并保存」才会生效；点击「返回」可回到列表继续调整。保存后，智能体无法再调用被移除的工具，相关定时任务会暂停，确认依赖后才能恢复。

如果工具来源正被团队智能体、运行中的任务或定时任务使用，请先确认影响范围并修复相关依赖，再停用或删除它。外部服务可能执行不可撤销的操作，请在启用工具前确认团队的数据使用要求和该服务的权限范围。

## 逐次确认可能修改数据的调用

部署方开启调用确认后，系统在调用可能修改数据的 MCP 工具之前，会先询问发起任务的成员。确认卡显示在对话中正在等待的步骤下方，列出工具源、工具、说明、这个工具属于写入数据、删除数据还是类别未知，以及将要发送的完整参数：

- **允许本次调用**：按显示的参数执行这一次调用。
- **本次会话中始终允许**：当前会话中这个工具的后续调用也自动允许；会话结束或工具定义变化后即失效。
- **拒绝并跳过**：不执行这次调用。
- 三分钟内没有决定，这次调用会被跳过。

决定后，确认请求会在对话中留下一行记录。你在其他页面时，页面上会出现提示，点击即可回到该对话；浏览器标签页标题也会显示有几项操作在等待确认。

服务标注为只读的工具直接执行，不会询问；同时标注为只读和删除数据的工具按没有标注处理。服务标注为写入或删除数据的工具可以选给智能体，每次调用都会确认。没有任何标注的工具在负责人或管理员确认类别之前不能选给智能体；助手使用它们时，每次调用都会确认。调用使用添加工具源时连接的账号，所以任何成员的调用都以该账号的身份执行。定时任务没有人可以确认，其中对这类工具的调用会被跳过。

### 确认工具类别

服务对工具的标注不准确或没有标注时，负责人和管理员可以记录每个工具实际会做什么：

1. 在工具源的操作中（卡片右侧的 **⋯** 菜单）选择 **确认工具类别**。
2. 为每个工具选择 **只读**、**写入数据** 或 **删除数据**。低于服务标注的类别不会出现在选项中。
3. 选择 **保存**。修改从下一个任务开始生效。

确认为只读的工具直接执行，不再询问；没有标注但已确认类别的工具可以选给智能体。服务之后如果修改了某个工具的定义，原来的确认不再生效，列表会提示重新确认。只有确实不会修改数据的工具才应确认为 **只读**。

## 运行 n8n 工作流

部署开启 n8n 工作流工具后，连接 n8n 实例级 MCP 服务（地址以 `/mcp-server/http` 结尾）的 MCP 工具源，可以把单个 n8n 工作流作为工具提供。每个批准的工作流都在 n8n 中运行已发布版本并等待结果，所以每次都按同样的方式运行。

1. 在 n8n 中发布工作流，并打开 **Available in MCP**。可以批准由 Webhook 或定时触发的工作流。
2. 在 Bowhead 中，从工具源的操作（卡片右侧的 **⋯** 菜单）中选择 **n8n 工作流**。没有发布或没有开放给 MCP 的工作流只显示数量，不列出名称。
3. 点工作流旁的 **审批**。按工作流对数据做了什么选择类别，填写给模型看的说明，并检查输入格式，也就是 Webhook 请求体的字段。草稿列出了已发布版本读取的字段，请补上类型并标出必填字段。
4. 点 **批准**。从下一个任务开始，这个工作流就是一个工具。

助手在任何任务中都可以使用已批准的工作流。要让某个自定义智能体使用一个工具源的工作流，请在 **团队设置 → 插件** 中用 **n8n 工作流** 模板新建插件，再在智能体中选择这个插件。

注意事项：

- 一次运行最多等 5 分钟，定时任务中最多 15 分钟。更长的运行会报告仍在运行，并附 n8n 中的执行链接。
- 如果工作流在 n8n 中重新发布，运行会以“版本已变化”停下，直到你审阅并批准新版本。
- 只读工作流直接运行，定时任务中也一样。会写入或删除数据的工作流每次运行都要请发起任务的成员确认，并且需要部署开启逐次确认。
- 工作流以授权这个工具源的 n8n 账号运行。n8n 询问权限时，只授予读取工作流、运行工作流和读取执行记录。
- 已批准的工作流不需要导入 n8n 自己的工具就能运行。导入 `execute_workflow` 会让助手不经批准就能运行任何开放给 MCP 的工作流，所以请不要选它。
- n8n 会限制来自同一地址的 MCP 请求（默认每 5 分钟 100 次）。Bowhead 会控制在限额以内；n8n 管理员可以用 `N8N_MCP_SERVER_RATE_LIMIT` 调高限额。
