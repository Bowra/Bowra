# Third-party license maintenance

English | [简体中文](第三方许可.md)

Complete translation of the current maintenance contract. [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) records distributed component names, versions, licenses, copyright notices, and bundled license text. [The English review inventory](third-party-license-review.md) and its [Chinese edition](第三方许可审查.md) lists licenses needing attention. These files are generated by `scripts/check_third_party_notices.py`; do not edit them manually.

## Coverage

| Source                       | Included components                                                                                                      | License source                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Frontend `package-lock.json` | Everything installed by `npm ci --omit=dev`, including platform optional/devOptional entries; only dev entries excluded. | Installed `node_modules` metadata/LICENSE, then local npm cache, then lockfile license field. |
| `uv.lock`                    | Runtime dependency closure for workspace members, equivalent to `uv sync --all-packages --no-dev`, excluding dev groups. | Installed `.venv` metadata/license files or local uv cache.                                   |
| Sandbox Node lockfile        | Retained sandbox Node dependency declarations.                                                                           | Same procedure as frontend npm packages.                                                      |
| Selected image contexts      | Base images, apt/apk packages, pinned pip packages, Chromium downloaded by Playwright, uv, and tiktoken dictionaries.    | [image_components.json](../config/third_party/image_components.json).                         |
| Vendored source material     | Third-party material embedded in source, such as Lucide icon paths.                                                      | Registry `vendored` entries and `config/third_party/licenses/`.                               |

The reviewed registry `image_contexts` selects the application and executor Dockerfiles from a fixed set of known contexts. The unsupported legacy Python sandbox Dockerfile is absent from Community; its Skill source and Node dependency lock remain. An operator-provided sandbox image needs its own complete installed-component and license inventory.

Generation is offline and makes no network requests. This inventory does not itself grant redistribution permission or change the root license.

## Updating after a dependency change

1. Update dependency definitions and lockfiles normally with npm or `uv add`/`uv lock`, or modify the appropriate Dockerfile.
2. Install relevant dependencies with `make install-frontend` and `uv sync --all-packages --no-dev`. If a component's license text becomes unavailable and it was not already listed under Components without a bundled license text, `--write` fails without writing, protecting existing texts. When a new package truly has no bundled license file, verify that fact before explicitly using `uv run python scripts/check_third_party_notices.py --write --allow-missing`. Missing Playwright `browsers.json` also prevents generation.
3. Register added base images/system/pip packages and their SPDX licenses in `image_components.json`. Pip installation accepts exact `name==version`; requirements/constraints/editable/unpinned forms are rejected. Register installers such as global npm installs or curl-to-shell commands through `components[].installer_match`. Register newly vendored materials and preserve their license files in `config/third_party/licenses/`.
4. Run `make third-party-notices`, which regenerates the notices and both review editions and formats them.
5. Review the generated review-inventory diff. Flag new GPL, AGPL, LGPL, SSPL, BUSL, missing-license, or non-SPDX entries in the change/review for the responsible maintainer to decide whether to retain them. The script does not automatically remove dependencies or approve their distribution.
6. Commit lockfiles, generated inventories, and registry changes together.

## Checks

`make lint` run the generator with `--check`. It computes a dependency fingerprint from production lockfile names/versions/license fields, Python runtime closure, Dockerfile/image components, and canonical registry content, and compares all generated headers. Checking requires neither `node_modules` nor `.venv`.

Dev-only changes do not affect the fingerprint. Production/runtime/image dependency changes without regenerated inventories fail and request `make third-party-notices`. Unregistered Dockerfile components and unsupported installation syntax also fail. `third-party-license-texts` records the bundled-text count and is checked against actual entries to catch truncation/manual changes. Canonical registry JSON ignores formatting/key order; `GENERATOR_VERSION` participates in the fingerprint and must advance for generator-format changes.

## Known limits

- Operator-provided sandbox images are outside this source inventory; inspect their complete installed dependencies before redistributing them.
- Debian/Alpine system packages are not version-pinned; the registry records licenses by package name. The image is authoritative for exact copyright files; see the next section.
- System libraries installed by Playwright are recorded as one aggregate component and vary with Playwright version.

## License texts and source for image system packages

The application image (`bowhead-app`) contains Debian system packages under GPL and other copyleft licenses, such as git, poppler-utils, and fonts-wqy-zenhei.

- **License texts**: each Debian package's copyright and license file is kept in the image at `/usr/share/doc/<package>/copyright`. The docs cleanup in `deploy/Dockerfile.app` removes only the remaining documentation and man pages, and the build asserts that the git and poppler-utils copyright files exist, failing if they are missing. Run `dpkg-query -W` inside the container to list the installed packages and their exact versions.
- **Corresponding source**: corresponding source for these Debian packages is available from the Debian archives; exact versions can be looked up by package name and version on [snapshot.debian.org](https://snapshot.debian.org/).
- **Contact**: for help obtaining source or license texts, contact the administrator of your deployment.

Bundled Skill catalog terms still require separate review; a dependency inventory does not override restrictive source-material licenses.
