# 第三方许可

[English](third-party-licenses.en-US.md) | 简体中文

Bowra 随产品分发的第三方依赖登记在仓库根的 [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)（名称、版本、许可证，以及宽松许可要求保留的版权声明与许可原文）。需要留意的许可单独列在 [`第三方许可审查.md`](第三方许可审查.md)。许可审查同时提供独立的[英文版](third-party-license-review.md)。这些文件都由 `scripts/check_third_party_notices.py` 生成，不要手改。

## 覆盖范围

| 来源                                          | 取什么                                                                                     | 许可证从哪里读                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `packages/bowhead_frontend/package-lock.json` | `npm ci --omit=dev` 会安装的全部条目（含平台二进制等 optional 与 devOptional，只排除 dev） | `node_modules` 内的 `package.json` 与 LICENSE；未安装时读本机 npm 缓存；再退回锁文件 `license` 字段 |
| `uv.lock`                                     | 各 workspace 成员的运行时依赖闭包（等同 `uv sync --all-packages --no-dev`，不含 dev 分组） | `.venv` 已安装包的 `METADATA` 与许可文件；未安装时读本机 uv 缓存                                    |
| `python_sandbox/node_deps/package-lock.json`  | 保留的沙箱 Node 依赖声明                                                                   | 同前端                                                                                              |
| 选定的镜像构建上下文                          | 基础镜像、apt/apk 系统包、pip 固定版本；另含 Playwright 下载的 Chromium、uv、tiktoken 词表 | [`config/third_party/image_components.json`](../config/third_party/image_components.json) 登记      |
| 源码内嵌素材                                  | 例如移植进前端源码的 Lucide 图标路径                                                       | `image_components.json` 的 `vendored` 与 `config/third_party/licenses/`                             |

登记表的 `image_contexts` 从固定的已知上下文中选择应用和执行器 Dockerfile。社区版不包含不受支持的旧 Python 沙箱 Dockerfile，保留其 Skill 源码和 Node 依赖锁。运营者提供的沙箱镜像需要独立的完整已安装组件与许可清单。

生成过程完全离线，不访问任何网络。

## 加依赖后怎么更新

1. 按平常方式改依赖并更新锁文件（`npm install`、`uv add` / `uv lock`，或编辑 Dockerfile）。
2. 保证本机装好了对应依赖：`make install-frontend && uv sync --all-packages --no-dev`。如果有组件读不到许可原文、且上一版清单里它并不在「Components without a bundled license text」中，`--write` 直接失败且不写文件，避免在没装依赖的机器上把许可原文静默删掉；新包确实不带许可文件时，确认后用 `uv run python scripts/check_third_party_notices.py --write --allow-missing` 生成。读不到 playwright-core 的 `browsers.json`（Chromium 版本）时同样失败。
3. Dockerfile 新增了 apt/apk 包、pip 包或基础镜像时，先在 `config/third_party/image_components.json` 登记其 SPDX 许可证；未登记会直接报错。pip 只接受 `name==version` 精确版本，`-r`/`-c`/`-e` 与未锁版本都会报错；`npm install -g`、`curl … | sh` 这类安装器必须在 `components[].installer_match` 里登记后才能通过。源码里新移植了第三方素材时，在 `vendored` 里登记并把许可原文放进 `config/third_party/licenses/`。
4. 运行 `make third-party-notices`，重新生成许可清单及中英文审查文件（会顺带执行 prettier）。
5. 看 `docs/第三方许可审查.md` 的 diff：新出现 GPL、AGPL、LGPL、SSPL、BUSL、许可证缺失或非 SPDX 的条目时，在提交说明或评审里写明，由负责人决定是否保留；脚本和检查都不会替你删依赖。
6. 把锁文件、所有生成物和登记表放在同一个提交里。

## 检查怎么工作

`make lint`执行 `scripts/check_third_party_notices.py --check`：

- 只根据锁文件、Dockerfile 与登记表计算依赖指纹（生产依赖的名称、版本与锁文件许可字段；Python 运行时依赖；镜像组件；登记表内容），与所有生成物头部 `<!-- third-party-inventory: ... -->` 里的指纹比对。不需要 `node_modules` 或 `.venv`。
- 只改 dev 依赖不会改变指纹；生产依赖、运行时依赖或镜像组件有任何增删或版本变化，而清单没重新生成，检查失败并提示运行 `make third-party-notices`。
- Dockerfile 里出现未登记许可证的系统包、pip 包或基础镜像，或出现解析不了的安装方式时同样失败。
- `THIRD_PARTY_NOTICES.md` 头部的 `<!-- third-party-license-texts: N -->` 记录附带许可原文的组件数，检查会与正文实际条目数比对，防止原文被截断或手改。
- 指纹里还包含登记表的规范化内容（与 JSON 缩进、键序无关）和脚本常量 `GENERATOR_VERSION`；改变生成格式时要递增它。

## 已知局限

- 运营者提供的沙箱镜像不在本源码清单范围内；重新分发前需检查其全部已安装依赖。
- Debian/Alpine 系统包未锁版本，许可证按包名登记；精确的版权文件以镜像内为准，见下一节。
- `Playwright install-deps chromium` 装的系统库随 Playwright 版本变化，只作为一个整体条目登记。

## 镜像内系统包的许可原文与源码

应用镜像（`bowhead-app`）包含 GPL 等 copyleft 许可的 Debian 系统包，例如 git、poppler-utils、fonts-wqy-zenhei。

- **许可原文**：每个 Debian 包的版权与许可文件保留在镜像内 `/usr/share/doc/<包名>/copyright`。`deploy/Dockerfile.app` 清理文档时只删除其余文档与 man 页，并在构建时断言 git 与 poppler-utils 的版权文件存在，缺失即构建失败。在容器内用 `dpkg-query -W` 可列出所装包及其精确版本。
- **对应源码**：这些 Debian 包的对应源码可从 Debian 官方归档获取；精确版本可在 [snapshot.debian.org](https://snapshot.debian.org/) 按包名与版本号检索下载。
- **联系方式**：如需协助获取源码或许可原文，请联系当前部署的管理员。
