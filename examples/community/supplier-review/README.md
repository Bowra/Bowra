# Supplier review: make the trade-offs visible

English | [简体中文](README.zh-CN.md) | [All examples](../README.md)

**Synthetic scenario:** a team needs a helpdesk service for 80 users, ready within eight weeks, with a first-year budget of USD 24,000 before tax. It wants an annual commitment and usable exports when it leaves.

## Run the task

Attach these three invented proposals, then paste [task.md](task.md):

- [Atlas proposal](proposal-atlas.md)
- [Beacon proposal](proposal-beacon.md)
- [Cedar proposal](proposal-cedar.md)

If Markdown attachments are unavailable, paste the three files into the conversation with their filenames. Ask for a decision memo first. Request a separate DOCX only when **Word documents** (`bowra-docx`) is available to the selected Agent; a filename in an answer does not establish that a downloadable file exists.

## A useful result

Look for a comparable cost table, explicit disqualifiers, references to proposal sections, and follow-up questions that could change the decision. The cheapest first year is not automatically the best fit. Use the [review criteria](review-criteria.md) to inspect the answer; a recommendation is conditional on evidence, not a claim that any fictional vendor has been verified.

Try a follow-up: “Assume we add 20 users at the start of month 7. Update the costs and explain which budget decisions change.”
