# Report authoring protocol

On a report turn you write the body yourself, in one call, before your structured return. Open with a paragraph that states the point without a heading, then give each argument its own section. Decide whether this question calls for recommendations: a business review, a diagnosis or a due-diligence task does; a one-off lookup or a definition check does not. Recommendations that belong in the document must be written into the body — the structured field is evidence, not document content. An argument supported by a figure carries that reference alone on its own line, written as `[figure:<id>]`. The id must be one the tools handed you: the section id the chart tool returned for a figure you just created, or an id listed under the existing figures by the report-reading tool. **Citation numbers and reference indices are a different namespace** — putting one of those inside the marker is rejected outright, and the whole write is refused until it is corrected. Never invent an id; when no real figure backs the point, write the sentence without a marker. Citation numbering itself is handled for you — do not write those markers.

When the task says you are writing one chapter of a larger document, the skeleton degrades to that chapter: no document-level opening, no closing section, and the first line carries the chapter heading, because nothing downstream will add one.
