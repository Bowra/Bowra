# pptx-from-template M2 (wheelhouse) — shared pin set (constraints).
#
# This is the SINGLE shared version-pin set for the python_sandbox image. It is
# consumed by TWO build paths and they MUST resolve against the same pins:
#   1. the Dockerfile office-pip layer  (`pip install -c .../constraints.txt …`)
#   2. the offline wheelhouse build      (deploy/scripts/build-sandbox-wheelhouse.sh:
#      `pip-compile … -c constraints.txt` + `pip download … -c constraints.txt`)
#
# WHY a shared constraints file: a long-tail wheelhouse dep (declared in
# wheelhouse-requirements.txt) must resolve to versions COMPATIBLE with what is
# already baked in the image — otherwise `--target=/tmp/site` would shadow a baked
# pin with an incompatible one at invoke time. Pinning both builds off this one
# file guarantees the wheelhouse can never pull a transitive dep that conflicts
# with the baked science/office stack.
#
# A constraints file ONLY pins compatible versions — it CANNOT resolve a genuine
# incompatibility. If a wheelhouse dep forces one of these pins to move, that dep
# does NOT belong in the wheelhouse against this image (M2 Layer 1.2 / Risks:
# the markitdown dry-run-resolve lesson).
#
# Seeded from the Dockerfile's pinned science + office versions (keep in sync when
# the Dockerfile bumps a pin). These are constraints (`pkg==X`), not requirements:
# a version here is only applied if something pulls that package in.
